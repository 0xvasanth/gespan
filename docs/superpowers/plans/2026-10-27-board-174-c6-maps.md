# Board #174 C6: codebase map (2026-10-27)

Paths are relative to the repository root. HEAD a77a4235.

In short:
- The store's board-wide reads are already linear. `query_cards` and its `load` read one statement per table, and `LATEST_RUN_SQL` uses one windowed read. No quadratic work was found in the store.
- The quadratic work is in the apps:
  - Native: `sync_handles` retain loops, `lookup_requests`, and per-column count queries;
  - Tauri: per-card scans of every board link, and `detail.cards.find` inside `agentOf`.
- Neither app windows the board layout's columns or swimlanes (ruling C4-d). List and table already window: Native with `uniform_list`, Tauri with `useWindowedRows`.
- Tauri has no arrow-key focus between cards. Native has no screen-reader announcements for board-layout keyboard drags, and its cards aren't Tab stops.

## 1. Store (`crates/board-store`)

- `src/views.rs`:
  - `load` (`:156`) reads cards with a join on columns and meta, then labels, projects, field values, links and run events. Each is one statement, mapped through a `HashMap` index. It is linear.
  - `LATEST_RUN_SQL` (`:112`): `ROW_NUMBER() OVER (PARTITION BY card_id …)` over `board_activity`, using `board_activity_card_idx`.
  - `board_facts` (`:332`): three id sets and the field options.
  - `query_cards` (`:567`) filters with `HashSet` tests (`any_value`, `:487`) and does one stable sort.
  - `latest_run_events` (`:124`) is public. Native reads it; Tauri has no command for it.
  - `check_spec` / `check_layout` (`:630`, `:639`) run on writes only (`:715`, `:777`).
- `src/meta.rs`:
  - `card_extras` (`:446`) is board-wide (meta, projects, labels, subtask counts).
  - `column_card_count(conn, column_id) -> (usize, usize)` (`:408`) works per column. Native `load` calls it once per column (`crates/gespan-gpui/src/board.rs:618-621`).
- `src/ops.rs`:
  - `get_board` (`:301`): three statements. `LIVE` (`:22`) is a `NOT EXISTS` on the meta primary key.
  - `set_column_display` (`:965`) writes colour, limit and collapsed together.
- `src/relations.rs:157` `blocked_cards` and `src/links.rs:153` `board_links` are one statement each. `src/agent.rs:75` `running_card_ids` filters `board_links`.
- `src/schema.rs`: `board_cards` has `UNIQUE (board_id, number)` (an index on `board_id`) and `board_cards_column_idx (column_id, position)`. Activity has `(card_id, created_at DESC)`.
- `src/migrate.rs`: the v3 comment and subtask copies have no `ORDER BY rowid` (R35).
- `Cargo.toml`: rusqlite 0.40.2 with `bundled, hooks`. The `trace` feature provides `Connection::trace(Option<fn(&str)>)` (a fn pointer, so counting uses a thread-local counter).
- No `examples/` folder yet. `ensure_tables` is public (`lib.rs:61`). `gespan-core`'s `Service::open` (`crates/gespan-core/src/board/mod.rs:35`) shows the open sequence: busy timeout and WAL.

## 2. Native (`crates/gespan-gpui/src`)

- `board/column.rs`:
  - `render_column` (`:47`) builds `body: Vec<AnyElement>` with one `render_card` per card plus the drop line (`:98-108`);
  - the body div `.overflow_y_scroll().children(body)` sits at `:258-280`, with the composer after it;
  - `render_collapsed` draws a strip with no cards;
  - `COLUMN_WIDTH = 280`.
- `board/views.rs:176` `column_cards`: filter by column and `card_matches`, then sort by `rank` (a `HashMap`). It is called per column per render.
- `board.rs`:
  - `reload` (`:533`) waits while dragging or lifted;
  - `poll` (`:560`) does a full `service.get` per tick while a card is lifted (`:568-579`);
  - `load` (`:599-720`) runs on the UI thread with about 15 reads, a per-column `column_card_count` loop and a `field_distinct_values` per text/number/date/url field;
  - `sync_handles` (`:727-752`) retains with `detail.cards.iter().any` (quadratic) and creates focus handles without `tab_stop(true)` (`:743`, `:749`).
- `board/card.rs:122`: `track_focus(focus).tab_index(0)`, which is not a Tab stop (R65). `:52` finds labels by linear search (labels are few).
- `board/keyboard.rs`:
  - `focused_card` (`:102`);
  - `move_card_focus` (`:192`) uses `visible_ids` and focuses the handle directly, with no scroll;
  - `lift_card` (`:236`); `kb_drag` slot moves (`:267-330`).
- `board/drop.rs`: `card_drop_index(tops, heights, pointer_y)` (`:9`). `board.rs:973` `card_drag_over` already maps slots among measured cards (`:1010`), so unpainted cards are handled.
- `board/swimlanes.rs`:
  - `card_lane_keys` (`:87`);
  - `lane_cell` (`:114`) calls `column_cards` per lane and column;
  - `lane_announcement` (`:363`) uses `Role::Status` (`:537-541`);
  - `render_swimlanes` (`:376`) uses `.overflow_scroll()` and renders every card.
- `board/selection.rs:77` `display_order`: the board layout is column-major and ignores lanes.
- `board/link_status.rs`:
  - `lookup_requests` (`:396`) scans all links per PR link (quadratic);
  - `read_link_sessions` (`:452`) does `all.iter().find` per key;
  - `rebuild_chips` (`:513`).
- `board/list.rs:150` `layout_spec` parses `views.layout` JSON on every call, including `layout_kind` per render (R77). `:604` `uniform_list` is the list-layout pattern.
- `transcript.rs:574-600`: `ListState::new(count, ListAlignment::…, px(320.))` plus `list(...)`, the variable-height pattern for C6-5/C6-7.
- `runtime.rs:1235` `answer_pending`: `call.reply.send(Ok(..))` (`:1275`) runs before `record_ticket_change` (`:1276`) (R26).
- `shell/session_groups.rs:2025` `set_work_item` calls `invalidate_chrome` (`:2042`), and `agent_changed_ticket` (`:2080`) goes through it (R27 is done).
- `input.rs:241-246`: `set_secret`'s doc line sits above `tab_stop` (R66).
- Tests: `board/tests.rs` (8,459 lines) declares `mod agent_wiring; mod link_run;` at the end. The fixture `open` (`:45`) uses a 1,400×1,400 window. `native:test` runs gpui tests with `--test-threads=1`. The `native-dev` profile uses opt-level 1.
- `shell/quick_open.rs:680-760`: the Native "New session from ticket…" tests (draft = title after fetch, key on failure, GitHub URL refused).

## 3. Tauri (`src/`)

- `features/board/ui/kanban/KanbanBoard.tsx`:
  - `DndContext` with `closestCorners` for cards and `MeasuringStrategy.Always`;
  - `columns.map(KanbanColumn)` and `cardsByColumn` (`columnCards` per column);
  - `DragOverlay` in a portal, so the active slot is a 2 px line.
- `ui/kanban/KanbanColumn.tsx`: the body (`overflow-y-auto`) maps every card into `SortableContext` (`verticalListSortingStrategy`). The collapsed strip has no cards, and its aria-label has no count (R56).
- `ui/kanban/KanbanCard.tsx`: `useSortable`, with `aria-pressed={selected}` (always false with a selection set, R82) and `aria-label="Card #N, title"`.
- `ui/kanban/announcements.ts`: `where(place)` gives "{column}, position {i} of {total}". The positions come from data (`placeOfCard`), so they survive windowing.
- `ui/kanban/keyboardCodes.ts`: Space starts, Space or Enter ends, Escape cancels. There are no arrow handlers outside a lift (no arrow focus in Tauri).
- `ui/kanban/Swimlanes.tsx`:
  - `moveBetweenCells` (`:36`) steps by droppable rects of `cell:` containers;
  - cell ids are `cell:{lane}|{column}`, and the cards inside use `{lane}|{card}`;
  - one `overflow-auto` scroller renders every lane and card;
  - collapsed columns draw expanded (R87).
- `model/windowing.ts`: `visibleRange` and `useWindowedRows` (fixed row height) are used by `BoardList.tsx` and `BoardTable.tsx`. The fallback viewport is 640 px in happy-dom.
- `ui/BoardView.tsx`:
  - `refresh` (`:552`) runs 10 reads in parallel, including `listActivity(id, null, 200)` → `latestEventByCard`. On a large board, failed state older than 200 rows is lost;
  - query effect (`:851-880`): `queryBoard` on every spec change, with no debounce (R80);
  - `shownDetail` (`:892`), `visibleCards` (`:962`), `displayOrder` (`:985-1014`): the board layout is column-major and ignores swimlanes;
  - `labelsOf` (`:1718`); `linkChipsOf` (`:1808`) and `agentFactsOf` (`:1855`) scan every `boardLinks` row per card; `agentOf` (`:1866`) runs `detail.cards.find` per card;
  - bulk paths use `ids.includes` inside filters (`:1417`, `:1456-1459`);
  - `renderCard` (`:1909`) creates new closures every render (no memo; windowing bounds the cost);
  - the root `onKeyDown` handles Escape for the selection only (`:2176-2190`); drawer Escape lives on the drawer `aside` (`CardDetail.tsx:393`), so it needs focus inside (R45).
- `ui/CardWorkSections.tsx:124` `commitEstimate`: `setEditing(false)` on a rejected value lets the effect at `:103` reset the text (R67).
- `ui/CardDrawerParts.tsx:411`: the comment textarea's Escape bubbles to the drawer's close (R45).
- `model/cardProps.ts:157` `encodeField` (R68).
- `ui/BoardLayouts.test.ts`: the fake backend (`handlers`, `seed`, `emitBoardChanged`) is file-local. `describe("windowing")` (`:1036`) opens small, then grows to 1,000 cards (commit 42373e53).
- `src/app/App.tsx:952`: palette entries `board-create-card`, `board-switch`. There is no "New session from ticket…" (ruling 19 deferred it to Phase C).
- `features/sessions/data/sessionStore.ts`: the ticket sanitizer, plus prettier-only hunks (for example `:1077`) (R17).
- `src/test/invokeCommands.test.ts` checks that TS command names are registered in Rust. `src/test/legacyNames.test.ts` rejects the old product names anywhere.
