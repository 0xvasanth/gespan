> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #174 before the single PR:
- the board layout's columns and the swimlanes layout render only what is on screen in both apps, so a 1,000-card board opens, filters and drags smoothly;
- drag and drop, keyboard moves, focus, Shift ranges and screen-reader announcements keep working with that windowing;
- performance budgets with 1,000-card tests in the store and in both apps;
- every deferred ledger item is fixed here or listed under "Accepted limits" with a reason;
- a user guide, a runnable verification script for the #174 manual checks, and a final parity pass.

**Architecture:**
- **Store first (Lane S).** A deterministic seed module and a `seed_board` example give both apps and the manual script the same 1,000-card board. Store tests pin statement counts and time budgets for every board-wide read. Two board-wide reads replace per-item loops: `column_card_counts`, and a Tauri `board_latest_run_events` command so Tauri stops guessing failed state from the last 200 activity rows. A column display patch removes the colour/limit/collapsed overwrite race. Small store and tracker fixes land in two batches.
- **Native (Lane N).** Each expanded column body becomes a GPUI `list` with a `ListState` per column (`transcript.rs` is the pattern). Swimlanes become one `list` of flattened rows: a lane header row, then bands of 4 cards per cell. Focus and keyboard drags scroll the target into view before focusing.
- **Tauri (Lane T).** A variable-height window (estimate first, then measured) renders card slots plus spacer gaps, and keeps the focused card and the dragged card mounted. Swimlanes use the same row model as Native. Tauri gains arrow-key focus between cards, which #174 asks for and windowing makes necessary.
- **Docs (Lane D)** come last: `docs/board.md`, the verification script and the parity pass.

**Tech Stack:** Rust (board-store, tracker-client, gespan-core, GPUI, src-tauri), React, dnd-kit, Vitest with happy-dom, Bun.

## Global Constraints

- Same branch and a single PR. Commits are plain, with no tool attribution. No local Cubic review on this branch (ledger ruling 6).
- Shared crates keep hard-coded `version`/`edition` (no `.workspace = true`).
- Plans, docs and tests use repository-relative paths only (`src/test/legacyNames.test.ts`).
- **No schema change in C6.** `SCHEMA_VERSION` stays 5, and `shared_contracts.rs` changes only if an error string changes.
- **Performance budgets.** Deterministic counts are the main guard. Times are generous ceilings that the unwindowed code fails. If a budget fails on a correct implementation, stop and report the measured number. Never loosen a budget inside a task.

  | Measure | Where | Budget | Why |
  |---|---|---|---|
  | Statements per board-wide read (`query_cards`, `card_index`, `card_extras`, `get_board`, `board_links`, `blocked_cards`, `latest_run_events`, `column_card_counts`) | `cargo test -p gespan-board-store` | The same count at 10 and at 1,000 cards | Catches per-card queries (N+1) independently of machine speed |
  | `query_cards`: 1,000 cards, a 3-row filter (label, priority, `linked: failed`) plus a priority sort | same, debug build | ≤ 150 ms | A debug build with `-O0` SQLite is about 5× slower than release, so release stays well under one 30 ms frame budget |
  | Rendered cards in an expanded board column | gpui and Vitest tests, 1,000 cards | ≤ 60 per column | A 1,400 px column holds at most about 33 compact cards. 60 leaves room for overscan and pinned cards, and is still 16× under 1,000 |
  | Rendered cards in swimlanes | same | ≤ 60 × visible columns | Same reasoning per column of the grid |
  | Native `load()` | gpui test, `native-dev` (opt-level 1) | ≤ 100 ms | `load` runs on the UI thread after every data-version change. 100 ms is the limit for a change to feel instant |
  | Native open (load and first draw) / filter (search edit, query, redraw) | gpui test | ≤ 400 ms / ≤ 150 ms | The open budget is one perceptible pause in the test harness. A filter must keep up with typing |
  | Tauri open (mount until cards are painted) / filter (search change until results are painted) | Vitest happy-dom | ≤ 2,000 ms / ≤ 750 ms | Today's unwindowed mount takes about 5.6 s, so this fails without windowing. happy-dom runs React mounts about 5–10× slower than WebKit, so this is ≤ 300 ms / ≤ 100 ms in the app |
  | Manual, release builds, both apps | `docs/native/verification.md` | Open ≤ 300 ms, keystroke to results ≤ 100 ms, a drag with no visible stutter | What a person notices. Checked by hand (C6-18) |

  Timing tests live in their own test files and use a 15 s Vitest timeout. Native timing tests run with `-- --test-threads=1`, as `native:test` does.
- **Windowing rules (both apps):**
  - Only expanded columns window. A collapsed strip mounts no cards (as today).
  - Always mounted (pinned): the card that has focus, the card being dragged (pointer or keyboard), and the card whose drawer is open.
  - A reload that leaves a column's card ids unchanged keeps its scroll position. When the ids change, the card at the top of the view stays at the top if it still exists.
  - Keyboard focus or a keyboard drag that moves to an unmounted card first scrolls it into view, then focuses it or draws the drop line there.
  - Shift ranges, bulk actions and announcements count from the data (display order), never from mounted elements.
  - Overscan: Tauri renders 4 cards beyond each edge. Native uses `CARD_LIST_OVERDRAW = px(240.)`.
  - Tauri first-guess heights: `CARD_ESTIMATE = { comfortable: 76, compact: 44 }` px plus a 6 px gap. A measured height replaces the guess per card id. A height change from a toggle or an edit in the other app re-measures.
- **Swimlanes row model (both apps):** rows are a lane header, then bands. Band `b` of a lane holds cards `[4b, 4b+4)` of every cell in that lane (`LANE_BAND = 4`). A lane with no cards has its header and one empty band. A drop anywhere in a cell's bands targets that cell and appends (ruling C5-k). Lane header rows stay mounted and carry one drop target per column, which keyboard drags use to reach another lane.
- **Display order with swimlanes is lane-major:** lane by lane, then column by column inside a lane, then by position. Shift ranges and bulk actions use it in both apps. It was column-major, which is not the order on screen.
- **Keyboard (both apps):**
  - ↑/↓ move focus to the previous or next visible card in the column. ←/→ move to the same index in the next column that has visible cards, clamped (the Native C1-5 rule).
  - In swimlanes, ↑/↓ cross into the neighbouring lane in the same column.
  - Tauri gets this through `nextCardFocus`. Native keeps `move_card_focus`.
  - Native cards become real Tab stops (`tab_stop(true)`), as Tauri cards already are.
- **Announcements:** Native board-layout keyboard drags announce through a `Role::Status` element with Tauri's exact strings:
  - "Picked up card #{n}, {title}. {column}, position {i} of {total}."
  - "Card #{n} is over {column}, position {i} of {total}."
  - "Dropped card #{n} in {column}, position {i} of {total}."
  - "Moving card #{n} was cancelled. It is back in {column}, position {i} of {total}."

  `{total}` is the column's full visible count, never the mounted count. Tauri cards get `aria-description="{i} of {total} in {column}"`. The Native column label reads "{name}, {total} cards".
- **Search:** Tauri waits 150 ms after the last keystroke before running the search query (`SEARCH_DEBOUNCE_MS`). Filter rows, sort and view changes run at once. Native runs the query synchronously, within the filter budget.
- **Estimate grammar (both apps, C3-3/C3-6):**
  - Accepted: `90`, `90m`, `1h`, `1h 30m`, `1.5h`, `.5h`, `0.5h` and `1.25h`, rounded to the minute.
  - Rejected: `1.m`, `0x10`, `1e3`, negative values and zero-length units.
  - The error text is "Use minutes or hours, like 90, 90m, 1h 30m or 1.5h".
  - Text the user typed stays in the field after a rejection.
- **Column display writes are patches** (`update_column_display`), so collapsing a column never resets a colour or WIP limit the other app just set.
- Verification before each commit: `bun run check`, and `bun run native:check` when `crates/` changes.

## Review Focus

1. **The other app writes while you are scrolled deep in a 1,000-card column.** The poll or board-changed reload keeps the same card at the top. It never jumps to the top or leaves a blank gap. Tests in C6-5 and C6-11.
2. **Keyboard focus or a lifted card moves onto a card that isn't mounted** (scrolled away, or 50 cards down). It lands on the right card, scrolls it into view, keeps focus after a wheel scroll away and back, and the announcement says "position 51 of 1000". Tests in C6-6 and C6-12.
3. **A Shift range from an unmounted anchor to a card far below,** on the board and in swimlanes. It selects exactly the display-order slice (lane-major in swimlanes). Tests in C6-6, C6-7, C6-12 and C6-13.
4. **A pointer drag into a windowed column that is scrolled, filtered or sorted.** The drop index maps back among all the column's cards (hidden cards keep their places). A sorted column still only appends (ruling C4-c). Tests in C6-5 and C6-11.
5. **Card heights change after mount** (density toggle, labels added in the other app, a long title edit). The window re-measures, nothing overlaps or leaves a gap, and the next drop lands where the line showed. Tests in C6-5 and C6-11.

## Accepted limits

One line each. The user-visible ones also go into `docs/native/parity.md` (C6-18).

- R2: a self-hosted Plane workspace literally named "browse" is read as Jira Data Center. Ruling 2's shapes can't tell them apart, and the name is unlikely.
- R4, R5, R8, R28: Jira transition edge cases (lost `allowedValues` keys, entries without id, status-id fall-through, double pick). The agent still gets the field list and a clear refusal, and these need live Jira shapes we can't record here.
- R9–R12: Plane connect and response edge cases. Typos fail with a clear error on first use, and the HTTP client keeps `redirects(0)`.
- R14, R15: provider error text on an expired token is understandable as is, and keychain reads per resolve are cheap.
- R19: a ticket's title or status change doesn't re-render the session row until the next refresh. The chip itself is right.
- R20, R21: test fakes and the Plane connect argument naming. No user effect.
- R22, R25: hub duplication and slot limits belong to the shared MCP endpoint (#123). Loopback only.
- R23: an agent may see "app gone" for a write that landed. R26 makes the chip show the result.
- R29, R30: crate API visibility and lint scope. Root `bun run check` lints tracker-client.
- R31, R32: remote sessions don't fill ticket title and status; refresh errors are announced but quiet; a cosmetic loading race. Remote ticket work is out of #174's local scope.
- R34: `session_store.rs` keeps its own `validate_id`. Same rule, no shared crate there.
- R40, R41, R90, R91: narrow read-then-write windows and non-atomic two-step writes. Each shows an error toast on failure, and the store guards its invariants.
- R42, R44, R60, R62, R70, R75: test and code-shape nits with no user effect.
- R49 (part): a swallowed setting read error and silently ignored blank board names. The next action shows the state, and nothing is lost.
- R50, R55: rare keyboard and delete-wording edge cases. The store guard still enforces.
- R52 (part), R54 (part), R69 (part), R74 (part), R88 (part): extra tests or wrapper tests for paths already covered at the store or component level; the hard-coded "user" actor on a restored card's move row; the Markdown toolbar's pending selection and native undo history (browser limits); a move skipped when its card is gone.
- R76 (part): add-filter element ids use the field index. Not user-visible.
- R77 (part): leaving the table drops an unsaved title, as the composer does.
- R53 (part), R56 (part), R84 (part), R86 (part): "Pick a date…" opens the drawer in Native (documented difference); the label builder is only partly shared; collapsed strips aren't draggable; hover-only and non-optimistic face edits; over-WIP toast wording, and no toast on bulk moves (a bulk move isn't a drop).
- R57: the Archive view briefly shows a card on expiry. It settles on the next refresh.
- R58 (part), R59 (part): untraced read-back, and a converted card with no own "created" row (by design).
- R61 (part): no 800 px scroll-to-comment test. The 1,400 px fixture covers the code path.
- R64, R70: no focus trap in the app-wide Modal, and ⌘N over the drawer. Both are app-wide behaviour outside the board.
- R72: views are validated strictly on write only, and both apps ship from this one PR.
