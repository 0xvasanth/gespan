# Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A built-in Kanban board with boards, columns, cards and an activity log. Cards can link to a session, a Pilot or a Flow run, and they move forward on their own as that linked work starts and finishes.

**Architecture:** Board data lives in four normalized SQLite tables, with all reordering done in Rust transactions so positions stay contiguous and every move writes an activity row atomically. The frontend is a `board` app view whose columns use the in-house `useAnimatedReorder` hook (no new DnD dependency), with cross-column drops hit-tested through its `externalDrop` callbacks. Auto-movement is a single pure rule (`autoMoveTarget`) applied when a linked session or Flow run changes state.

**Tech Stack:** Rust + rusqlite, React 19 + TS, Vitest, the existing `src/shared/hooks/useAnimatedReorder.ts`.

**Spec:** Conversation decisions from 2026-10-23 ("inbuilt Kanban-style board … boards, cards, activity"; external board integrations later) and the Design Decisions below.

## Global Constraints

- Tables are created by `crate::board::ensure_tables(conn)?;` at the end of `session_store::migrate`. No numbered migration. `PRAGMA foreign_keys` is already ON.
- Commands take `State<'_, SessionStore>`, return `Result<_, String>`, and emit `"rebase:board-changed"` with payload `{ boardId }` after writes.
- No new npm dependency for drag and drop.
- Column roles are `"todo" | "doing" | "review" | "done" | null`. Each role appears at most once per board.
- External board integrations (Linear, Jira, …) are **out of scope**. The `link_kind` column is the extension point for them.
- Commits carry no Claude or co-author attribution. Run a local Cubic review before pushing or opening a PR.

## Design Decisions (my calls, flag if wrong)

- **Default columns** on a new board: Backlog (`todo`), In Progress (`doing`), Review (`review`), Done (`done`).
- **Positions are integers 0..n-1 per column**, renumbered inside the move transaction. No fractional indexing, because boards are small and local.
- **Auto-move only goes forward.** When linked work starts, the card moves to `doing`. When it completes, the card moves to `review` if the board has that role, otherwise to `done`. When it fails, the card stays put and the activity log records `failed`. A card never moves to a column left of where it currently is, so a card the user already dragged to Done stays there.
- **Column deletion** is refused while the column holds cards (`"Column has N cards"`).
- **One link per card** (`link_kind`, `link_id`), kinds `"session" | "pilot" | "flow-run"`. Pilot links follow the Pilot's spawned sessions: a Pilot-spawned session that settles counts as activity for any card linked to that Pilot.
- **Actor** on activity rows is `"user"` or `"system"`.

## Review Focus

1. A card dropped onto a column of a *different board* (or a stale column id) must be rejected, not orphaned. `board_card_move` errors with `"Column not on this board"` (Task 1 test).
2. Two auto-move events for the same card at once, such as a Flow run finishing while the user drags it, must not duplicate positions. Moves serialize on the connection mutex, and a test asserts positions stay 0..n-1 after interleaved moves (Task 1 test).
3. When a linked session or flow run is deleted, the card keeps its link id, shows "Linked work no longer exists" and doesn't throw (Task 4 test).
4. Dropping a card in its own position is a no-op that writes **no** activity row (Task 1 test).
5. A board with no `doing` column (the user deleted it) means auto-move on start is skipped, not an error (Task 2 test).

**Interfaces:**
- Tables:

```sql
boards(id TEXT PRIMARY KEY, name TEXT NOT NULL, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL)
board_columns(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, name TEXT NOT NULL, position INTEGER NOT NULL, role TEXT)
board_cards(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, column_id TEXT NOT NULL REFERENCES board_columns(id), title TEXT NOT NULL, body TEXT NOT NULL DEFAULT '', position INTEGER NOT NULL, link_kind TEXT, link_id TEXT, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL)
board_activity(id TEXT PRIMARY KEY, board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE, card_id TEXT REFERENCES board_cards(id) ON DELETE CASCADE, kind TEXT NOT NULL, actor TEXT NOT NULL, from_column TEXT, to_column TEXT, detail TEXT, created_at INTEGER NOT NULL)
-- indexes: board_cards(column_id, position), board_cards(link_kind, link_id), board_activity(board_id, created_at DESC), board_activity(card_id, created_at DESC)
```

- Activity `kind`: `"created" | "moved" | "edited" | "linked" | "unlinked" | "started" | "completed" | "failed" | "deleted"`. A `deleted` row keeps `card_id = NULL` and stores the title in `detail`.
- Commands, serialized camelCase:
  - `board_list() -> Vec<Board>`
  - `board_get(boardId) -> BoardDetail { board, columns: Vec<Column>, cards: Vec<Card> }`, sorted by position
  - `board_create(name) -> Board`, which creates the default columns
  - `board_rename(boardId, name)`, `board_delete(boardId)`
  - `board_column_create(boardId, name, role?) -> Column`, `board_column_update(columnId, name, role?)`
  - `board_column_move(columnId, index)`, `board_column_delete(columnId)`
  - `board_card_create(columnId, title, body?) -> Card`, `board_card_update(cardId, title, body)`
  - `board_card_move(cardId, columnId, index, actor)`
  - `board_card_link(cardId, linkKind?, linkId?)` (passing nulls unlinks)
  - `board_card_delete(cardId)`
  - `board_cards_for_link(linkKind, linkId) -> Vec<Card>`
  - `board_activity(boardId, cardId?, limit) -> Vec<Activity>`, newest first
  - `board_card_record(cardId, kind, detail?)`, which appends a `system` activity row without moving the card

### Task 2: Frontend model and the auto-move rule

**Files:**
- Create: `src/features/board/model/board.ts` (types, invoke wrappers, `subscribeBoard(boardId, onChange)` listening to `"rebase:board-changed"`), `src/features/board/model/autoMove.ts`, `src/features/board/model/autoMove.test.ts`

**Interfaces:**

```ts
export type ColumnRole = "todo" | "doing" | "review" | "done";
export type BoardColumn = { id: string; boardId: string; name: string; position: number; role: ColumnRole | null };
export type BoardCard = { id: string; boardId: string; columnId: string; title: string; body: string; position: number; linkKind: CardLinkKind | null; linkId: string | null; createdAt: number; updatedAt: number };
export type CardLinkKind = "session" | "pilot" | "flow-run";
export type LinkedWorkEvent = "started" | "completed" | "failed";

export function autoMoveTarget(columns: BoardColumn[], current: BoardColumn, event: LinkedWorkEvent): BoardColumn | null; // null = stay
export function onLinkedWork(kind: CardLinkKind, id: string, event: LinkedWorkEvent): Promise<void>;
```

`onLinkedWork` runs `board_cards_for_link`. For each card it loads its board's columns, computes `autoMoveTarget`, then either calls `board_card_move(card, target, Number.MAX_SAFE_INTEGER, "system")` or, when the target is null, `board_card_record(card, event)`. Both paths record the event.

  - `started` on a board with no `doing` column → null.

**Files:**

**UI behavior:**
- With no boards, show an empty state with a "Create board" button. The last open board is remembered in localStorage key `rebase:open-board` (wrapped in try/catch).
- Columns scroll horizontally. Each has a header (name and count, rename inline, role menu, delete disabled with a tooltip while non-empty), and "+ Add card" at the bottom (Enter creates, Esc cancels).
- Drag uses one `useAnimatedReorder(cardIds, onReorder, "y", externalDrop)` per column. `externalDrop.onMove` hit-tests `[data-board-column]` rects under the pointer to show a drop indicator, and `externalDrop.onDrop` calls `board_card_move(id, targetColumn, index, "user")`. Reorders within a column call the same command. Columns themselves reorder with `useAnimatedReorder(…, "x")`.
- Updates are optimistic: apply the move locally, then reconcile on `rebase:board-changed`. If the command fails, revert and show the error toast the app already uses.
- Clicking a card opens `CardDetail`: edit fields, link picker (session / Pilot / Flow run from existing snapshots), "Open linked work" (navigates to the session, Pilot or Flow run view), and the activity timeline (`"Moved from In Progress to Review · system · 2m ago"`).
