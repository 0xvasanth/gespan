**Schema:** `schema::VERSION = 3`, `ensure_tables(conn)`, `migrate::{version, run}`.

**Activity detail conventions.** Extras edits go through `log_edit` (ops.rs:221), which writes `kind="edited"`, `actor="user"` and a `detail` string:
- Priority: `"priority: High"`.
- Dates: `"due: YYYY-MM-DD"` or `"due: none"`, same pattern for `start:`. The date is the local day from `day_label`.
- `"estimate: 90m"` or `"estimate: none"`.
- `"projects: N"` (the count, not the names).
- Labels: `"labels: A, B"` (sorted case-insensitively) or `"labels: none"`.
- Subtasks: `"subtask added: T"`, `"subtask done: T"`, `"subtask reopened: T"`, `"subtask deleted: T"`.
- Comments: `"comment added"`, `"comment edited"`.
- Archive: `"archived"`, `"unarchived"`.
- Relations: `"relation: blocks #N"` / `"relation: relates to #N"`, `"relation removed: …"`.
- Fields: `"{field name}: {value}"`.

Other kinds:
- Links: kind `linked` or `unlinked` (from `add_link`/`remove_link`, and from `link_card`), detail `"kind:ref"`. Tickets log `"ticket: KEY"`.
- `created` / `edited` (title or body) / `moved`: `detail` is `None`; `moved` fills `from_column`/`to_column` with column names.
- `deleted`: detail is `"#N title"`.

Native renders edits as `"Changed {detail} · actor"` (`detail.rs:111` `activity_text`). Tauri's `activityAction` (`src/features/board/ui/boardFormat.ts:127`) shows only `"Edited"` and ignores the detail.

**How the board is chosen**
- `load()` (`board.rs:335–363`) calls `service.default_board()` on every reload and sets `open_board_id`.
- `default_board` is used only there.
- A switcher would need a `selected_board_id` field that `load()` prefers, falling back to `default_board()` when that board is missing. Reload already runs from `reload` (:294), the poll (:309) and window activation (:199).

**Header** (`header.rs:142` `render_header`)
- Row contents in order:
  1. Kanban icon and a static "Board" label (:157–168).
  2. `board-search`.
  3. `board-filter` with an active-count pill.
  4. A spacer.
  5. `board-new-task`.
- The switcher would replace the static "Board" label at :157–168.
- Search: `query()` :70; `card_matches()` :84 handles `#N` as an exact number match and otherwise a lowercase title substring, then applies the project, label and priority filters. Each filter matches if any value matches, and the three filters combine with AND.
- Counts: `count_label()` :107 returns `shown/total` while searching or filtering.
- Filter popover: `render_filter` :264, with selectors `board-filter-menu`, `board-filter-list`, `board-filter-project-{i}`, `board-filter-label-{i}`, `board-filter-priority-{p}`, `board-filter-clear`.
- Header buttons are tab stops via `filter_focus` / `new_task_focus`; `presses()` treats Enter and Space as a press.

**Drawer** (`detail.rs`, `detail/view.rs`)

**Mouse drag today**
- The card uses `.on_drag(DraggedCard, …)` (`card.rs:~90`), which calls `begin_card_drag`.
- The column body (`column.rs:~240`) has `on_drag_move::<DraggedCard>` calling `card_drag_over` (`board.rs:608`). That computes the slot from the measured `card_anchors` bounds through `drop::card_drop_index`.
- `on_drop` calls `drop_card` (:671), which maps the visible slot to the full slot (`full_slot` :649, so it is filter-aware), then `resolve_card_drop`, then `service.card_move(…, "user")`.
- The drop line renders where `drop_target` points.
- Columns drag by their header with `DraggedColumn` → `column_drag_over` / `drop_column`.
- Reloads are deferred while `dragging` (`pending_reload`), and `forget_finished_drag` (:262) recovers drags released off the board.

**"Move to…" and focus**
- Each card has a `FocusHandle` in `card_focus` (`tab_index(0)`, `focus_visible` accent border).
- The card's `on_key_down` handles only `"enter"`, which opens `open_card_actions` (`board.rs:741`). That builds a `crate::popover::Menu` with "Open card" and "Move to {column}" items (ids `move-{index}`), and picking one calls `move_card_to` (:732, index `usize::MAX`).
- "…" is `board-card-menu-{n}`.
- `on_key` (:797) handles only Escape, closing layers innermost first.
- **There is no arrow-key focus movement and no Space pickup.** Keyboard drag would need new state (for example `kb_drag: Option<(card_id, column_id, slot)>`), handled in the card's `on_key_down`. It could reuse `drop_target` to draw the drop line and `card_move` to commit.

**Persisting the last-opened board**
- `BoardView.store: crate::runtime::Database` (`Arc<Mutex<Store>>`). Lock it with `crate::runtime::locked(&self.store)?`.
- Then use `Store::setting(key) -> Result<Option<String>>` and `Store::save_setting(key, value)` (`crates/gespan-core/src/store.rs:192`, `:207`). These write the `native_settings` table, or the shared extras JSON in shared mode.
