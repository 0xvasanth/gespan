# Board #174 C5: codebase map (2026-10-26)

Paths are relative to the repository root.

In short:
- The store already holds the C5 columns: column `color` / `wip_limit` / `collapsed`, `board_settings` (`run_with`, `write_back`, `ticket_status_changes`, `auto_move_json`), labels, fields, relations, links and `agent` comments.
- Almost none of it reaches a UI. Neither app reads or writes `board_settings`, and neither shows column colour or WIP limits.
- There is no label rename, delete or merge, and no field create, rename or delete UI. Field values are not validated by kind.
- Auto-move is hard-coded twice (Rust and TS). Native passes an empty running set to the query engine.
- The Tauri app has no agent ticket tools.

## 1. board-store today (schema v4)

- `crates/board-store/src/schema.rs:4`: `VERSION = 4`.
  - `V3_TABLES` already creates `board_settings` (`:146-152`), `board_fields`, `board_card_field_values`, `board_card_relations` and `board_card_links`.
  - `V3_COLUMNS` added `board_columns.color`, `wip_limit` and `collapsed`. `V4_TABLES` holds `board_views`.
- `crates/board-store/src/migrate.rs:17`: `STEPS = [(2,to_v2),(3,to_v3),(4,to_v4)]`.
  - `run` takes an Immediate transaction, re-reads the version and runs the steps above it.
  - `column_exists` / `table_exists` helpers are available for a `to_v5`.
- `settings.rs`: `BoardSettings { run_with, write_back, ticket_status_changes, auto_move_json }`, which is `Serialize` only.
  - `board_settings` (`:27`): a missing row means every switch on.
  - `set_board_settings` (`:57`) is a full-row upsert. **No caller in either app.**
- `ops.rs`:
  - `ROLES` includes `cancelled` (`:10`).
  - `RECORD_KINDS = ["started","completed","failed"]` (`:27`).
  - `DEFAULT_COLUMNS` (`:28`) is Backlog/In Progress/Review/Done.
  - `create_board` (`:340`) inserts a `board_settings` row.
  - `set_column_display(column_id, color, wip_limit, collapsed)` (`:965`), with `check_color` for six hex digits and a WIP limit of at least 1.
  - `delete_column` refuses while live or archived cards remain (C2-b).
- `labels.rs`: `list_labels`, `create_label` (`:44`, case-insensitive unique name, six-hex colour), `set_card_labels` and `set_label_many`. **No update, move, delete or merge.**
- `fields.rs`:
  - `FIELD_KINDS = ["text","number","date","select","checkbox"]` (`:9`);
  - `create_field` (`:37`), `list_fields`;
  - `set_field_value` (`:120`) checks only that the value is JSON and logs "{name}: {value}";
  - options are a JSON array of names (see `crates/gespan-gpui/src/board/quick.rs:169` `field_options`);
  - **no update, move or delete, and no per-kind validation.**
- `views.rs`: field rows (`:409`) parse JSON values and match them exactly; select values are checked against the options. `query_cards(…, running: &HashSet<String>)` (`:543`). `delete_view` (`:769`).
- `comments.rs:8`: `COMMENT_AUTHORS = ["user","agent"]`. `add_comment(conn, card_id, body, author)` logs "comment added".
- `links.rs`:
  - `card_links` (`:126`) reads per card;
  - `ticket` / `board_tickets` / `set_ticket` (role `ticket`);
  - `LINK_KINDS` (`ops.rs:14`) is session, pilot, flow-run, pr, worktree, jira, linear and plane;
  - **no board-wide read of non-ticket links.**
- `relations.rs:34`: `add_relation(card, related, kind)`, where `card_id` **blocks** `related_card_id`. It refuses cycles and cross-board relations.
- `meta.rs:12`: `PRIORITIES = ["None","Low","Medium","High","Urgent"]`.
- `crates/gespan-core/tests/shared_contracts.rs:446` lists the shared tables. New v5 tables go here.

## 2. gespan-core

- `src/board/extras.rs` holds the `Service` wrappers for every store call (the C4 list).
  - It already has `add_agent_comment` (`:295`) and `set_column_display` (`:130`).
  - **There is no settings, templates, label-manage or field-manage wrapper.**
- `src/board/auto_move.rs`:
  - `LinkedWorkEvent {Started, Completed, Failed}` (`:7`);
  - `auto_move_target` (`:34`) is forward-only and ignores `auto_move_json`;
  - `on_linked_work(service, kind, id, event)` (`:52`).

  It mirrors `src/features/board/model/autoMove.ts`.
- `src/board/linked_turns.rs:24`: `LinkedTurns { open: HashMap<(session, gen), Option<pilot>> }`. Its open turns are exactly Native's "running" set, but nothing exposes them yet.
- `src/ticket_bridge.rs`:
  - `TicketTool` (`:33`), `refusal(tool, may_change_status, read_only)` (`:72`) and `answer(tickets, ticket, tool)` (`:372`), with `Effect` and `Answered`;
  - `Server::start(session, ticket, may_change_status, read_only)` (`:164`);
  - `tool_definitions` (`:511`) has `additionalProperties: false`;
  - `mcp_stdio` (`:619`);
  - errors `STATUS_OFF`, `READ_ONLY` and `APP_GONE` (`:27-29`).

  Everything here depends only on `crate::tickets`, which is `gespan_tracker_client::tickets` (`src/lib.rs:36`), so the pure part can move to `crates/tracker-client`.
- `src/tool_servers.rs:20` defines the `gespan_ticket` server for Claude, Codex and ACP. `src/tool/presentation.rs` holds the friendly labels ("Comment on ticket").
- `src/scm.rs`:
  - `pr_status(cwd) -> Option<Pr{number,title,url,state}>` (`:401`);
  - `diff_stats(cwd) -> DiffStats{files,additions,deletions}` (`:135`);
  - the checks reader is `inbox/github.rs:1082` `git_github_pr_checks_for`, which is `pub(super)`.

## 3. Native app (`crates/gespan-gpui/src`)

- `board.rs`:
  - `LinkLabel {Found, Missing}` (`:75`) is one label per card, built from the legacy single link in `resolve_links` (`:595`; session title or Pilot name only);
  - `card_tickets` / `stale_tickets` (`:146-152`) hold the ticket chip state.
- `board/views.rs:137-141`: `run_query` passes `&HashSet::new()` as the running set (C4-f).
- `board/turns.rs`:
  - the `BoardTurns` global (`:19`) and `install` (`:29`) run `on_linked_work` on a background queue;
  - `turn_started` and `turn_settled(store, session, turn, stopped, ok, cx)` (`:138`);
  - `pilots(cx)` lists Pilots.
- `board/column.rs`: role colour only (`:11`). **No column colour, WIP count or highlight.** `board/quick.rs:357` collapse keeps the colour and WIP limit.
- `board/header.rs`: the filter builder. Field rows for select use the options (`:460`); text, number and date offer only the held values (C4-h).
- `board/switcher.rs:117`: `create_board(name)` takes a plain name, with no template.
- `board/detail.rs` + `detail/view.rs`: `comment_author("agent") → ("Agent","A",true)`, plus the ticket chip and the field editors for the five kinds.
- `board/style.rs:26`: `next_label_color`, the same 8 colours as Tauri.
- `runtime.rs:535-575`: the ticket tools start through `ticket_bridge::Server::start`.
  - `read_only = settings.plan || access == ReadOnly`.
  - `may_change_ticket_status` (`:1100`) is a stub that returns `true` ("arrives with the board store").
  - `runtime/ticket_context.rs` builds the introduction from the tracker and key only.
- `conversation.rs:343`: `needs_approval()` is the Native "waiting for input" signal.
- `shell/app_views.rs:275-282` handles `board::Event` (`Close`, `OpenSession`, `LinkTicket`, `OpenPilot`). "Run with…" adds an arm here.
- `shell/session_groups.rs` + `ticket_chip.rs` hold the session ticket chip and link dialog. A per-session status toggle belongs in that chip's menu.
- `shell/quick_open.rs`: "New session from ticket…" (`start_from_ticket`) is the pattern for creating a linked session with a draft.

## 4. Tauri app

- `src-tauri/src/board.rs`: the commands listed in C4, plus `board_column_set_display` (`:463`) and `board_card_record` (`:332`). **No settings, templates, label-manage, field create/manage, or blocked-card commands.**
- `src-tauri/src/tickets.rs`: `ticket_resolve`, `ticket_fetch`, `ticket_connected`, `plane_status`, `plane_set_config`. **No tool execution.**
- `src-tauri/src/control.rs`:
  - `request_grant(host, namespace, token)` (`:161`). The "app" namespace needs an active turn with `app_allowed` (the `/operator` opt-in) and not an orchestrator or worker.
  - `serve` (`:218`) emits `gespan-control-request` to the window and waits 35 s for `control_reply`.
  - `configure_child` (`:466`) injects `GESPAN_APP_ENDPOINT` / `GESPAN_APP_TOKEN`.
- `src-tauri/src/control_cli.rs:83`: `APP_ACTIONS` (32 entries) and the `app` help text. Unknown fields are rejected.
- `src-tauri/src/fs.rs`: `git_diff_stats` (`:842`), `git_pr_status` (`:1179`) and `git_github_pr_checks` (`:1575`) cover PR and diff link status without a new command.
- `src/app/App.tsx`:
  - the `gespan-control-request` listener (`:11332`) routes `namespace === "app"` to `handleAgentApp`;
  - `boardLinkTargets` (`:13981-14030`): running if the session is busy, else completed, and a Pilot is running if its rail isn't idle;
  - `linkedTurns.current ??= createLinkedTurns(onLinkedWork)` (`:1838`).
- `src/features/agent-app/model/agentApp.ts`: `FIELDS` allow-list (`:171`), `fields()` (`:225`) and `handleAgentApp` (`:943`), which dispatches by prefix.
- `src/features/sessions/model/session.ts`: `sessionNeedsInput(session)` (`:809`) and `TurnIntent` (`"plan"` is Tauri's read-only turn). `ui/SessionTicketChip.tsx` is the session chip.
- `src/features/board/`:
  - `model/autoMove.ts` (`autoMoveTarget` and `onLinkedWork`, forward-only);
  - `model/board.ts` (wrappers);
  - `ui/boardFormat.ts` (`BoardLinkTarget` `:19`, `LABEL_COLORS` `:163`);
  - `ui/BoardColumnHeader.tsx` and `ui/kanban/KanbanColumn.tsx` (no WIP or colour);
  - `ui/BoardView.tsx` (`createBoard(name)` at `:890`);
  - `ui/BoardFilter.tsx`, `ui/BoardTable.tsx` and `ui/CardWorkSections.tsx` (field editors for five kinds).
