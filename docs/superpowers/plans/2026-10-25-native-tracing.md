# Native tracing foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gespan Native writes structured JSONL logs to a rotating, size-capped file in the platform log folder, records every panic to an fsync'd crash file, and offers "Open logs folder" and "Copy diagnostics" commands.

**Architecture:** A new `gespan_core::diagnostics` module owns everything: a JSON-lines `tracing` layer, a daily-rolling file writer with an injectable clock and startup pruning, the panic hook, and the two local actions. `gespan-gpui`'s `main.rs` calls `diagnostics::init` once after argument parsing and routes every `std::process::exit` through a helper that flushes the non-blocking writer first.

**Tech Stack:** Rust, `tracing` 0.1, `tracing-subscriber` 0.3 (`env-filter`, `fmt`, `registry`), `tracing-appender` 0.2 (`non_blocking` only), `tracing-log` 0.2, `chrono`, `serde_json`, `uuid`.

**Spec:** GitHub issue #68 (approved design), background in #45 Parts 1–2.

## Global Constraints

- Filter variable: `GESPAN_LOG` (`EnvFilter` syntax). Default level `info`.
- File name: `gespan-native.YYYY-MM-DD.jsonl`, one per day, in the platform log directory.
- Retention: keep 7 days **or** 50 MB in total, whichever is hit first; pruned at startup.
- Writes are non-blocking (`tracing_appender::non_blocking`); the `WorkerGuard` lives for the life of the process and is flushed on every `std::process::exit` path in `crates/gespan-gpui/src/main.rs`.
- Panic hook writes an fsync'd `crashes/<ts>.json` next to the logs, then calls the previous hook.
- Existing `catch_unwind` sites log what they caught at `warn`.
- "Open logs folder" and "Copy diagnostics" make no network calls.
- Gespan names only; `src/test/legacyNames.test.ts` must pass. Hotspots (`main.rs` mod list, `Cargo.toml` dep lists, lock file) get small additive edits; the lock file is regenerated by cargo.
- Verification gate: `bun run native:check`.

## Decisions made here (my calls, not in the issue)

1. **Log directories.** Release / dev (`--dev-data`):
   macOS `~/Library/Logs/dev.gespan.native/` / `~/Library/Logs/dev.gespan.native.dev/` (the bundle ids);
   Linux `$XDG_STATE_HOME/gespan-native/logs/` / `$XDG_STATE_HOME/gespan-native-dev/logs/` (fallback `~/.local/state`);
   Windows `%LOCALAPPDATA%\dev.gespan.native\logs\` / `%LOCALAPPDATA%\dev.gespan.native.dev\logs\`.
2. **Own daily writer instead of `RollingFileAppender`.** tracing-appender's roller has no injectable clock and no size cap, and the issue asks for rotation tests with a fake clock. `DailyFile` is ~80 lines and is wrapped in `non_blocking` as the issue requires.
3. **Pruning also runs on day rollover**, not only at startup, so a long-running app still honours the 7-day limit. The current day's file is never deleted; once it alone reaches the 50 MB budget, further lines that day are dropped, so a log storm cannot fill the disk.
4. **Line format follows the #45 shared contract** (`{ ts, level, target, message, app: "native", version, session_id?, span?, fields{}, event_id }`) through a small custom layer, rather than `fmt().json()` whose shape differs. #66 will document it; this module is the native writer of it. Span fields are merged into `fields`; `span` is the `outer:inner` span path.
5. **Dev builds also print a human-readable stderr layer** (as #45 Part 1 describes), so later `eprintln!` migrations (#69/#70) don't silence `bun run dev:native` output.
6. **Diagnostics are only initialised for the app path**, after argument parsing (the channel comes from `--dev-data`/`--gespan-data`). CLI helper subcommands (`visual-mcp`, `visual`, `app`, ssh askpass, `--version`, `--help`) stay unlogged. Every `std::process::exit` in `main.rs` still goes through the flushing helper, which is a no-op before init.
7. **Commands live in the `>` command palette** ("Open logs folder", "Copy diagnostics"). The Settings → Privacy & diagnostics section is #74's scope.
8. **"Copy diagnostics" contains no log lines.** Redaction (#67) hasn't landed, so the text is version, channel, OS/arch, the log folder with the home directory shown as `~`, the log file count and total size, and the crash file count with the newest crash file name.
9. The panic-hook test and the `init` end-to-end test are **integration tests** (`crates/gespan-core/tests/`), each its own process, because the panic hook and the global subscriber are process-wide and `gespan-core` unit tests run in parallel.

## Review Focus

- Two threads panicking in the same millisecond must produce two crash files, not one overwritten file → Task 4 test `same_millisecond_panics_get_distinct_files`.
- A panic *inside* the hook (e.g. unwritable crash dir) must not recurse or abort before the previous hook runs → Task 4 test `unwritable_crash_dir_still_runs_previous_hook`.
- An invalid `GESPAN_LOG` value must not disable logging → Task 2 test `invalid_filter_falls_back_to_info`.
- Non-log files in the log folder (crash dir, `.DS_Store`, other apps' files) must never be pruned → Task 3 test `prune_ignores_foreign_files`.
- `flush()` called twice, or logging after `flush()`, must not panic or hang → Task 5 test.

- Line: one JSON object + `\n` per event: `ts` (RFC 3339 UTC, ms), `level` (lowercase), `target`, `message`, `app: "native"`, `version`, `event_id` (uuid v4), `fields` (object, span fields then event fields, event wins), `span` (`outer:inner`, omitted outside spans), `session_id` (lifted from fields when present, removed from `fields`).

- [ ] Failing tests (in-memory `MakeWriter` over `Arc<Mutex<Vec<u8>>>`, `tracing::subscriber::with_default`):
  - `captures_event_fields`: `tracing::warn!(provider = "codex", attempts = 3, ok = false, "agent start failed")` → `level == "warn"`, `message == "agent start failed"`, `fields == {"provider":"codex","attempts":3,"ok":false}`, `app == "native"`, `version == "1.2.3"`, `event_id` parses as a UUID, `ts` parses as RFC 3339.
  - `span_fields_and_path`: event inside `info_span!("worktree", session_id = 7)` → `info_span!("git", action = "fetch")` → `span == "worktree:git"`, `session_id == 7`, `fields.action == "fetch"`, `session_id` absent from `fields`; event field with same name as a span field overrides it.
  - `one_line_per_event_even_with_newlines`: message containing `\n` → output has exactly 2 lines for 2 events, each valid JSON.
  - `filter_respects_gespan_log`: `filter(Some("gespan_core::git=debug"))` → a `debug!(target: "gespan_core::git")` is written, `debug!(target: "gespan_core::store")` is not, `info!` elsewhere is.
  - `invalid_filter_falls_back_to_info`: `filter(Some("=[bad"))` → error is `Some`, `info!` written, `debug!` not. `filter(None)` → info.
- [ ] Run → FAIL. Implement the layer (`on_new_span`/`on_record` store a `serde_json::Map` in span extensions; `on_event` merges scope fields root→leaf, then event fields). Run → PASS. Commit.

### Task 3: Daily file writer, rotation and pruning

**Files:**
- Create: `crates/gespan-core/src/diagnostics/rotation.rs`

**Interfaces:**
- Produces: `pub const MAX_DAYS: i64 = 7; pub const MAX_BYTES: u64 = 50 * 1024 * 1024;` `pub trait Clock: Send + 'static { fn today(&self) -> chrono::NaiveDate; }` `pub struct SystemClock;` (UTC date) `pub struct DailyFile<C: Clock>` implementing `std::io::Write`; `DailyFile::new(dir: PathBuf, clock: C, max_days: i64, max_bytes: u64) -> io::Result<Self>` (creates dir, prunes); `pub fn file_name(day: NaiveDate) -> String` (`gespan-native.2026-10-25.jsonl`); `pub fn prune(dir: &Path, today: NaiveDate, max_days: i64, max_bytes: u64) -> io::Result<Vec<PathBuf>>` (returns deleted files).
- Prune rule: only files matching `gespan-native.YYYY-MM-DD.jsonl`; delete those dated `<= today - max_days`; then, oldest first, delete until the total is `<= max_bytes`, never deleting `today`'s file.

- [ ] Failing tests (temp dir, `FakeClock(Arc<Mutex<NaiveDate>>)`):
  - `writes_to_todays_file_and_rolls_at_midnight`: write a line, advance clock a day, write → two files with the right names, each holding its own line.
  - `prune_drops_files_older_than_seven_days`: files for today-0…today-9 → today-0…today-6 remain.
  - `prune_enforces_total_size_oldest_first`: 4 files of 400 bytes with `max_bytes = 1000` → the two oldest go, today's remains.
  - `prune_never_deletes_today`: today's file alone exceeds the budget → it remains.
  - `prune_ignores_foreign_files`: `crashes/`, `.DS_Store`, `gespan-native.notadate.jsonl`, `other.2020-01-01.jsonl` all survive.
  - `rollover_prunes`: advancing the clock 8 days during writes removes the oldest file.
  - `drops_lines_once_today_reaches_budget`: `max_bytes = 100`, write 3 × 60-byte lines → file holds only the first line; `write` still returns `Ok(len)`.
  - `appends_to_existing_file_on_restart`: second `DailyFile` for the same day appends, not truncates.
