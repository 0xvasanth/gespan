# Board #174 C5: Customization and agent work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both apps get #174 Part 3 "Customization" and Part 4 "Agent work on the board", plus the Tauri half of Part 7:
- Customization:
  - a board settings page (name, icon/colour, default view);
  - a column manager (colour, WIP limit, role);
  - a label manager and priority renames;
  - custom-field management (7 kinds);
  - card display options with density;
  - swimlanes;
  - templates.
- Agent work:
  - link status per link;
  - "Run with…";
  - agent write-back;
  - configurable auto-move;
  - blocked cards;
  - agent fields;
  - Tauri agent ticket tools through `control.rs`.
- Carry-overs:
  - C4-f: live Native `linked: running`;
  - C4-h: text/number/date filter values.

**Architecture:** The rules live in `crates/board-store`, so both apps behave the same:
- a v5 schema;
- a settings patch API;
- templates;
- label and field management;
- auto-move rules;
- write-back;
- blockers;
- the "Run with…" prompt builder;
- card tools for agents.

The ticket-tool core (`TicketTool`, refusal rules, `answer`) moves from `gespan-core` into `crates/tracker-client`. Tauri can then enforce the same scope rules as the Native MCP bridge without depending on `gespan-core`. Native serves the agent tools over its existing `gespan_ticket` MCP server. Tauri serves them as `ticket.*` / `card.*` actions in the `control.rs` "app" namespace, executed by a Tauri command that reads the session's link itself. Each app keeps its own UI.

**Tech Stack:** Rust (board-store, tracker-client, gespan-core, GPUI, src-tauri), React, Vitest, Bun.

**Spec:** #174 Part 3, Part 4, Part 7 (Tauri transport) and the 2026-10-25 decisions comment. Parent plan `docs/superpowers/plans/2026-10-25-board-174.md` (Phase C row C5; the Tauri tools note under A9). Map: `docs/superpowers/plans/2026-10-26-board-174-c5-maps.md`.

## Global Constraints

- Same branch and single PR. Commits plain, no tool attribution. No local Cubic review on this branch (ledger ruling 6).
- Shared crates keep hard-coded `version`/`edition` (no `.workspace = true`).
- **Rulings that bind C5:** boards are global, with cards tagged by project. Descriptions are Markdown with a toolbar. New boards default to "Run with…" ON, agent write-back ON and ticket status changes ON. Ticket links on sessions and cards are independent, with no sync. Agents act on tickets only through tools.
- **Schema v5** (`VERSION = 5`; one new step `to_v5` in `migrate::STEPS`, idempotent):
  - `board_settings` + `icon TEXT`, `color TEXT`, `default_view_id TEXT`, `display_json TEXT`, `priority_json TEXT`. Defaults stay lazy: a missing row or NULL means the defaults.
  - `board_templates(id TEXT PRIMARY KEY, name TEXT NOT NULL, spec_json TEXT NOT NULL, created_at INTEGER NOT NULL)`
  - `board_session_settings(session_key TEXT PRIMARY KEY, may_change_status INTEGER)`. NULL means "follow the board".
- **Settings writes are patches.** `update_board_settings` changes only the fields it is given, so one app never resets a toggle the other just set.
- **Palette:** label and column colours come from the 8-colour palette `8a867e e5534b e0823d e8c547 3fb950 2bb3a8 4da3f5 a371f7` (`LABEL_COLORS` / `style::next_label_color`). Board icons are one of `board bug rocket check star flag bolt book`.
- **Columns:**
  - The WIP count shows `{total}/{limit}`. The header is highlighted when total > limit.
  - Dropping a card over the limit saves the move and shows the toast "Over the WIP limit ({n}/{limit})".
  - While filtered, the count reads `{shown}/{total}` and the limit compares against total.
  - Deleting a column that has cards offers "Move cards to…". It moves the live cards, then deletes. If archived cards remain, the C2-b refusal still applies.
- **Labels:** create, rename (unique ignoring case), recolour, reorder, merge and delete. A merge moves every card to the target label and rewrites saved-view `labels` rows. A delete writes one activity row per affected card, "label removed: {name}".
- **Priority scheme:** `PriorityScheme { names: [String; 5], hidden: Vec<u8> }`. The default names are `None Low Medium High Urgent`. Each name is 1–20 characters. Level 0 can't be hidden. Hidden levels leave pickers and filter values, but a card that already has a hidden level still shows it.
- **Custom fields:**
  - `FIELD_KINDS = ["text","number","date","select","multi-select","checkbox","url"]`.
  - Options are a JSON array of option names.
  - Values validate per kind:
    - text: string, at most 2,000 chars;
    - number: finite;
    - date: integer ms;
    - select: one option;
    - multi-select: an array of distinct options;
    - checkbox: bool;
    - url: `http://` or `https://`, at most 2,000 chars.
  - Renaming an option rewrites the stored values. Removing an option clears or strips its values.
  - Deleting a field removes its values, its saved-view filter rows and its table columns.
  - A field's kind can't change.
- **Display options:** `DisplayOptions { face: { labels, priority, due, subtasks, comments, linkStatus, number: bool, fields: Vec<field_id>, agentFields: Vec<"provider"|"model"|"cost"|"runTime"> }, density: "comfortable"|"compact", swimlane: "none"|"priority"|"label"|"project"|"field:<id>" }`.
  - The board default lives in `display_json`. A saved view may override it under `layout_json.display`; "All cards" uses the board default.
  - Defaults: every toggle on, no fields, no agent fields, comfortable, no swimlanes.
- **Swimlanes:** rows group the board layout. A drop into another lane changes the card's column. It also sets the lane value only for `priority` and select-field lanes; `label` and `project` lanes change the column only.
- **Templates:** list order is built-ins first, then saved templates by name.

  | id | Columns (role) | Labels | Fields | Other |
  |---|---|---|---|---|
  | `blank` | Backlog (todo), In Progress (doing), Review (review), Done (done) | — | — | same as `create_board` today |
  | `agent-pipeline` | Queued (todo), Running (doing), Needs review (review), Merged (none, `a371f7`), Done (done) | — | — | auto-move `prMerged → Merged` |
  | `bug-triage` | New (todo), Triaged (none), In progress (doing), Fixed (review), Closed (done), Won't fix (cancelled) | Bug `e5534b`, Regression `e0823d`, Needs repro `e8c547` | Severity: select `["S1","S2","S3","S4"]` | — |
  | `release-checklist` | To do (todo), In progress (doing), Blocked (none, `e5534b`), Done (done) | Docs `4da3f5`, QA `3fb950`, Ops `2bb3a8` | Release: text | view "By label" (list grouped by label) |

  - "Save as template" stores columns, labels, fields, views and settings, with no cards.
  - Creating a board from a template remaps column, label and field ids inside view specs, layouts and auto-move rules. Unmapped values drop (the C4 rule).
  - Built-ins can't be deleted: "Built-in templates can't be deleted".
- **Auto-move:**
  - Events are `started`, `needs_input`, `completed`, `failed`, `pr_opened` and `pr_merged`.
  - Each rule is `"default"`, `"stay"` or `{"column": id}`. The defaults are started=default, needs_input=stay, completed=default, failed=stay, pr_opened=stay, pr_merged=stay. "Default" is today's forward-only rule.
  - A custom column target moves the card there in either direction. A target column that no longer exists means stay. Invalid JSON reads as the defaults.
  - `pr_opened` and `pr_merged` fire at most once per card, deduplicated by an existing activity row of that kind.
- **Link status (one chip per link):**
  - session: `running` (open turn) > `waiting` (needs input) > `failed` (the latest activity for that link is failed) > `completed`;
  - Pilot: running or idle;
  - PR: open, merged or closed, plus checks passing, failing or pending when known;
  - worktree: branch name, plus diff stats `+a −d`.

  Status refreshes when the board opens and when a linked turn settles, off the UI thread, **never on a timer**. The running set passed to `query` is real in both apps (C4-f).
- **Blocked:** a card is blocked while any `blocks` relation points at it from a live card whose column role is not `done`/`cancelled`. A blocked card shows a lock. "Run with…" asks "#{n} is blocked by #{a}, #{b}. Run anyway?", with the buttons "Run anyway" and "Cancel".
- **Run with…:**
  - Shown only when the board's `run_with` is on.
  - The picker offers provider, model and project/worktree.
  - The session starts with `run_prompt(card)`, links to the card (kind `session`) and inherits the card's ticket.
  - `run_prompt` format, with empty sections omitted and a 20,000-char cap:

    ```
    Work on board card #{number}: {title}

    {description}

    Subtasks:
    - [ ] {title}
    - [x] {title}

    Comments:
    - {body}
    ```

    Comments are user comments only, the newest 10, oldest first.
- **Write-back** (when the board's `write_back` is on):
  - When a turn completes, every card linked to the session gets one comment with the turn's final reply, trimmed to 4,000 chars with "…". The author is `agent:<session_key>`. An empty reply writes nothing.
  - Agents tick subtasks with the card tools `card_subtasks` and `card_subtask_done {subtaskId, done}`, which are scoped to cards linked to the session.
  - `COMMENT_AUTHORS` accepts `user`, `agent` and `agent:<id>`. Both UIs label `agent*` as "Agent".
- **Agent fields** (`provider`, `model`, `cost`, `runTime`) are computed by each app from the card's linked sessions. They are never stored and appear only on the card face and as table columns.
- **Ticket status permission:** `may_change_ticket_status(session_key)` returns the session override when one is set. Otherwise it returns the strictest `ticket_status_changes` among boards whose cards link the session, or `true` when no card links it. "Agent may change ticket status" can be toggled per board (settings page) and per session (ticket chip menu).
- **Security:**
  - **Agent-supplied fields are filtered.** MCP schemas use `additionalProperties: false` and the server rejects unknown keys. Tauri `FIELDS` rejects unknown keys. A `key` naming another ticket is refused with "This session is linked to {key}". Every scope (ticket, cards, session) is read by the app at call time, never taken from agent input.
  - **Read-only sessions can't write.** `ticket_comment`, status moves and `card_subtask_done` are refused with "This session is read-only". In Native that covers plan mode and `AccessMode::ReadOnly`; in Tauri, a turn whose intent is `plan`.
  - **No ticket title in prompts.** The introduction names the tracker and key only (ruling 16). `run_prompt` never includes ticket snapshot fields or agent-authored comments. When the card has a ticket link and its title equals the ticket snapshot's title (case-insensitive, trimmed), `run_prompt` treats the title as ticket content: the first line becomes `Work on board card #{number}` with no title (ruling C5-a). Test this in C5-3.
  - **Tracker HTTP clients keep `redirects(0)`.** C5 adds no new HTTP client; any new one must use `redirects(0)`.
  - **Write-back comments are marked agent-authored** (`agent:<session_key>`) and render as "Agent".
  - **Blocked cards need confirmation** before "Run with…" starts.
  - The keychain token never reaches the agent. Tauri ticket and card actions need an active turn of the granted session; they don't need `/operator`.
- Verification before each commit: `bun run check`, and `bun run native:check` when `crates/` changes.

## Review Focus

1. **Settings written by both apps at once** (Native toggles write-back while Tauri renames the board). The patch API changes only the named fields. Tests in C5-1.
2. **Something a rule, default view, template or display option points at gets deleted** (column, view, label, field). A rule stays put, the default view clears, a template drops the value, and a display option ignores the missing field. Never an error. Tests in C5-1, C5-2 and C5-3.
3. **A session linked to several cards on boards with different settings.** Write-back comments only on boards with it on, and the stricter status permission wins. Tests in C5-1 and C5-3.
4. **The ticket link changes mid-turn** (unlinked or relinked while the agent calls a tool). The call uses the link at call time and never a key the agent supplied. Tests in C5-5 and C5-6.
5. **"Run with…" on a card whose tracker is disconnected, or that is blocked.** The session starts with the cached ticket inherited (tools then report "not connected"), and a blocked card asks first. Tests in C5-10 and C5-15.
