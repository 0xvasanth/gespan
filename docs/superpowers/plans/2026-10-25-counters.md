# Native failure counters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Count failures (and, where a rate matters, successes) by day, name and a fixed error kind in a database only Gespan Native opens.

**Architecture:** `gespan_core::diagnostics::metrics` owns a `Counters` store (one SQLite file, one `diagnostic_counters` table) and a process-wide instance behind `open`/`failure`/`success`/`track`. Call sites add one line each. Before `open` runs (tests, CLI paths) every call is a no-op. A thread-local capture lets tests see what a call site recorded without touching the global.

**Tech Stack:** Rust, rusqlite (workspace), chrono (UTC days, as the log files use), tracing for write errors.

**Spec:** GitHub issue #71 (approved design), background in #45 Part 3.

## Global Constraints

- Table `diagnostic_counters`, columns `day`, `name`, `error_kind`, `count`, `app_version`.
- Stored in Native's own database, never `gespan.db` (Tauri opens that too).
- `error_kind` is a fixed enum, never free text.
- No UI in this ticket.
- Gespan names only (`src/test/legacyNames.test.ts`).
- Shared files (`diagnostics/mod.rs`, `lib.rs`, gpui `main.rs`, Cargo files): small, additive edits only.

## My calls (not pinned by the issue)

1. **File:** `gespan-native.db` in the same folder as `gespan.db` (`dev.gespan.desktop/` in release, `Gespan Development/` in development). Native has no database of its own today, and #80 plans `diagnostics.db` for Tauri in that same folder, so the name says whose file it is. `metrics::database_path(gespan_db)` derives it, and `Counters::open` refuses a file named `gespan.db`.
2. **Success rows** use `error_kind = 'ok'`. That keeps the five columns as specified; `Count::kind` is `None` for them.
3. **Day** is the UTC date (`YYYY-MM-DD`), matching the log files' rollover.
4. **Names** are checked, not typed: `[a-z0-9_]` segments joined by `.`, at most 64 bytes. Anything else is dropped with a `warn` that logs only the length, so error text pasted into a name never reaches the table. Names stay strings so `agent.start.<provider>` can use `Kind::id()`.
5. **Synchronous writes** behind a `Mutex`, WAL and `synchronous=NORMAL`, `busy_timeout` 250 ms. An increment is one upsert. The panic hook uses `try_lock`, so a panic raised while the lock is held cannot deadlock.
6. **Classifying `String` errors:** `ErrorKind::of_message` maps the message to an enum value (timeout, auth, not found, network, otherwise `other`). The message is read but never stored.
7. **`mcp.start`:** Native starts no MCP servers itself (the provider CLIs do), so it has no call site. Listed as a follow-up.
8. **`git.command`** counts failed invocations only, not successes (there are many per refresh). Expected probe misses (for example `symbolic-ref` on a detached HEAD) count as `exit_status`; spawn failures count as `spawn_failed` or `not_found`.
9. **`agent.turn_error`** is recorded once per failed turn that was not cancelled, and skips model-catalog probes. Start failures return before the turn loop, so they are counted only under `agent.start.<provider>`. OpenCode turns run on a separate path and are a follow-up; OpenCode starts are counted.

## Review Focus

1. Recording before `open` (unit tests, `--check-data`): must be a silent no-op, never a panic or a stray file. Tested in Task 1.
2. A name carrying error text (`"git failed: /Users/…"`): must not be stored. Tested in Task 1.
3. The same `(day, name, kind)` recorded twice, or under another app version: twice increments one row; a new version gets its own row. Tested in Task 1.
4. A panic while the counters lock is held: the hook must not deadlock. Tested in Task 2.
5. `gespan.db` gains no tables even after counters are written through the real path. Tested in Task 2.

### Task 1: `metrics` store and API

**Files:**
- Create: `crates/gespan-core/src/diagnostics/metrics.rs`
- Modify: `crates/gespan-core/src/diagnostics/mod.rs` (one `pub mod metrics;` line)

**Interfaces:**
- Produces:
  - `pub enum ErrorKind { SpawnFailed, NotFound, Timeout, Auth, Network, Io, ExitStatus, Parse, Panic, Other }` with `ALL`, `code(self) -> &'static str` (`spawn_failed`, `not_found`, `timeout`, `auth`, `network`, `io`, `exit_status`, `parse`, `panic`, `other`), `from_code(&str) -> Option<Self>`, `of_message(&str) -> Self`, `of_spawn(&io::Error) -> Self` (NotFound → `NotFound`, else `SpawnFailed`), `From<&io::Error>`.
  - `pub struct Count { pub day: NaiveDate, pub name: String, pub kind: Option<ErrorKind>, pub count: u64, pub app_version: String }`.
  - `pub struct Counters` with `open(path: &Path, version: &str) -> Result<Self, String>`, `open_in_memory(version: &str)`, `record(&self, day: NaiveDate, name: &str, kind: Option<ErrorKind>) -> Result<(), String>`, `since(&self, first: NaiveDate) -> Result<Vec<Count>, String>` (sorted by day, name, kind).
  - Global: `open(path, version) -> Result<(), String>`, `failure(name: &str, kind: ErrorKind)`, `success(name: &str)`, `track<T, E: AsRef<str>>(name: &str, result: &Result<T, E>)` (success, or failure with `of_message`), `last_days(days: u32) -> Result<Vec<Count>, String>`, `database_path(gespan_db: &Path) -> PathBuf`, `capture<T>(body: impl FnOnce() -> T) -> (T, Vec<Count>)` (thread-local, for tests in either crate).
