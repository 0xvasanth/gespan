# Board #174 C2: codebase map (2026-10-26)

Paths are relative to the repository root.

I mapped both apps. A few things here affect the C2 plan, so they come first.

**Gaps that shape the plan**
- **Undo of delete:** board-store has nothing to restore a deleted card. `delete_card` hard-deletes, and every child row goes with it through `ON DELETE CASCADE` (schema.rs:45–131). Re-creating the card isn't a real undo either: `create_card` gets a new id and number, and card numbers are never reused. Two ways to make delete undoable: hold the delete until the toast expires (archive or hide the card first, then hard-delete), or add a store-level soft delete.
- **Native's wrapper is missing the new store functions:** `gespan_core::board::Service` (crates/gespan-core/src/board/mod.rs, extras.rs) has no wrappers for `archive_card`, `unarchive_card`, `archived_cards`, `move_cards` or `set_column_display`. They need adding before the GPUI app can use them.
- **Tauri has no commands for any of them either:** none of those five is imported in src-tauri/src/board.rs:6–12 or registered in src-tauri/src/lib.rs:373–405, and src/features/board/model/board.ts has no wrappers.
- **Delete column disagrees with the store:** both apps count only live cards, so a column holding only archived cards shows Delete as enabled. The store then refuses with "Column has N cards", because `delete_column` (ops.rs:469–482) counts archived cards too.
- **Unarchive doesn't restore the old spot:** it appends to the end of the column, so undoing an archive needs a `move_card` to the old index afterwards.

## 1. board-store (crates/board-store/src)

**Signatures**
- `pub fn archive_card(conn: &Connection, card_id: &str) -> Result<String, String>` — meta.rs:239. Returns the board id; does nothing if the card is already archived.
- `pub fn unarchive_card(conn: &Connection, card_id: &str) -> Result<String, String>` — meta.rs:255. Puts the card back at the end of its old column (`ids.push`, meta.rs:263).
- `pub fn archived_cards(conn: &Connection, board_id: &str) -> Result<Vec<Card>, String>` — meta.rs:272. Newest archive first.
- `pub fn move_cards(conn: &Connection, card_ids: &[String], column_id: &str, index: usize, actor: &str) -> Result<String, String>` — ops.rs:853.
  - Keeps the order given and skips duplicate ids.
  - Errors if any card is archived or on another board.
  - Writes one `moved` activity row per card that actually changed.
- `pub fn set_column_display(conn: &Connection, column_id: &str, color: Option<&str>, wip_limit: Option<i64>, collapsed: bool) -> Result<String, String>` — ops.rs:940.
  - It overwrites all three fields at once, so collapsing a column must pass the current color and WIP limit back in.
  - Colour must be six hex digits; the WIP limit must be at least 1.
  - It writes no activity row.
- `pub fn delete_card(conn: &Connection, card_id: &str) -> Result<String, String>` — ops.rs:736. Logs a `deleted` activity row with `card_id: None` and detail `#N title`, then deletes the card and renumbers its column.
- Related:
  - `move_card(conn, card_id, column_id, index, actor)` — ops.rs:602. Errors with "Card is archived" for an archived card.
  - `create_card(conn, column_id, title, body) -> Card` — ops.rs:491.
  - `Column { color, wip_limit, collapsed }` — lib.rs:69–78.

**How positions work with archived cards**
- `LIVE` (ops.rs:20–23) is the SQL filter "not archived". `column_card_ids` (ops.rs:144) and `get_board` (ops.rs:319) both apply it.
- Live cards keep contiguous positions 0..n-1. On archive, the rest of the column is renumbered without the archived card, which keeps its old, now stale `position` value.
- `create_card` counts only live cards (ops.rs:515).
- Board detail never includes archived cards, so the Archive view has to load them from `archived_cards`.
- `completed_at` exists in the schema but nothing writes it. "Done" means the card sits in the column with the `done` role.
- Existing test: tests/v3.rs:425 `positions_stay_contiguous_after_archive_and_bulk_move`; column display test at tests/v3.rs:502.

- Elements and their selectors:

  - Title, with a check icon when done (:134–158)
  - Subtasks bar: `board-card-subtasks-{n}` (:159)
  - Ticket chip (:191)
  - Meta row (:195–225): `#n`, priority glyph `board-card-priority-{n}` (:203, only shown when priority > 0), due `board-card-due-{n}` (:43–56), comment count, link chip, relative time

- **Where click handlers can go without breaking drag:** copy the "…" button (:245–249). It uses `.on_mouse_down(Left, |_,_,cx| cx.stop_propagation())` plus `.on_click` with `cx.stop_propagation()`. Add the same pair to the priority, due and labels divs, which already have ids.
- Priority is only rendered when it's above 0. Setting priority from the face of an unprioritised card needs a placeholder target.

**Column** (board/column.rs, `render_column` at :46)
- Header (:154–236) is the column drag handle (`on_drag(DraggedColumn)`). It holds:
  - The role ring
  - The name, or the rename input
  - The count `board-column-count-{i}`
  - Hover-only buttons: `board-add-card-top` → `open_composer` (:189–211) and `board-column-menu-{i}` → `open_column_menu` (:212–234)
- Body (:237–302) carries `on_drag_move::<DraggedCard>` and `on_drop::<DraggedCard>` (:241–253). A collapsed strip must keep these two handlers.
- Collapsed state is never read anywhere yet; the column is always `COLUMN_WIDTH` 280 wide (:7).
- **Existing column menu:** `enum Menu { Column { column_id, roles: bool } }` (board.rs:70). Pieces:
  - `open_column_menu` (board.rs:629) and `render_menu` (board.rs:890), a popover anchored to `column_anchors`
  - `column_items` (board.rs:943): Rename / Set role / Delete
  - `role_items` (board.rs:923)
  - `menu_row(id, label)` (board.rs:984), a div with role `MenuItem` and a `debug_selector`
  - Add new entries as more `menu_row(...)` items in `column_items`.

**Card menu**
- `open_card_actions` (board.rs:808) builds `crate::popover::Menu::new("Card actions", items, window, cx)` from `MenuAction::new(id, label)` items, separated by `MenuItem::Separator`.
- It subscribes with `cx.subscribe_in` and handles `MenuEvent::Picked(id, _)`, storing the result in `CardMenu` (board.rs:74).
- It is drawn with `crate::popover::menu_popover(&open.menu, Anchor::Slot(card_anchor), cx)` (board.rs:1114–1121).
- Test selectors come out as `menu-action-{id}`.

**Composer (quick add)**
- `open_composer` (board.rs:538) and `commit_composer` (board.rs:554).
- After Enter it closes: `if self.write(...) { self.composer = None; }` (:565–569). The hint reads "Enter to add · Esc to cancel" (column.rs:277).
- To keep it open, clear the input with `input.update(cx, |i, cx| i.set_text(String::new(), cx))` instead of setting `composer = None`.

**Quick-edit logic to reuse**
- board/detail.rs `open_choice` (:395) builds the priority and due menus; `apply_choice` (:454) does the writes, including the `due-pick` date picker.
- Labels: `toggle_label` (:628) and `open_picker` (:514).
- `done_column()` (:815) and `mark_complete` (:829) cover "Mark all as done".
- `delete_card` (:856) asks for confirmation with `window.prompt`.
- All of these assume the drawer is open (`detail_card()` and `card_detail.choice`). The card face needs a version anchored to the card, like `card_menu`.

**Toasts and notices**
- The board has no transient notice. Errors go to `self.error`, drawn as the inline `board-error` line (board.rs:1086–1098).
- App-wide building blocks:
  - `crate::notifications::surface::toast_frame()` (notifications/surface.rs:43) — the glass card used for the top-right stack
  - `notifications::errors::card(id, message, dismiss)` (errors.rs:5)
  - `crash_notice` in shell/report.rs:181 also uses `toast_frame`
- None of these auto-dismiss. An undo toast needs its own timer, e.g. `cx.spawn` plus `cx.background_executor().timer(..)`, the same way `_poll` works (board.rs:211).
- The closest existing "Undo" button is in session_review.rs:314 (`text_button`).
