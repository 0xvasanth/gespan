# Board #174 C4: Find and organize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Both apps get #174 Part 2 "Find and organize" and "Keyboard":
- search including the description;
- a filter builder with chips;
- sort;
- saved views as tabs;
- List and Table layouts;
- bulk select with a floating bar;
- board keyboard shortcuts;
- command palette actions.

**Architecture:** One query engine in `crates/board-store` (`views.rs`) evaluates a view spec (search, filter rows, sort) against a board and returns ordered card ids. Native calls it through `Service`, and Tauri through one command, so both apps agree exactly on what matches. Saved views live in a new v4 table. Each app keeps its own UI: Native renders List/Table with `uniform_list`, and Tauri with a small fixed-row windowing helper (no new dependency).

**Tech Stack:** Rust (board-store, gespan-core, GPUI, src-tauri), React, Vitest, Bun.

**Spec:** #174 Part 2 ("Find and organize", "Keyboard"). Parent plan `docs/superpowers/plans/2026-10-25-board-174.md` (Phase C row C4). Map: `docs/superpowers/plans/2026-10-26-board-174-c4-maps.md`.

## Global Constraints

- Same branch and single PR. Commits plain, no tool attribution.
- **Search:** case-insensitive substring over title **and description**. `#N` matches the card number exactly.
- **Filter rows** ("Where" first row, "and" after it): `{ field, op: "is" | "is_not", values: [...] }`, combined with AND. Within a row, values OR. The fields and their values:
  - `status`: column ids
  - `priority`: 0..=4
  - `labels`: label ids
  - `projects`: project paths
  - `due`: `overdue` | `today` | `next7` | `later` | `none`
  - `created` and `updated`: `24h` | `7d` | `30d`, meaning "within the last…"
  - `linked`: `running` | `failed` | `needs_review` | `none`
  - `field:<field_id>`: values are JSON-encoded field values
- **Linked-work states:**
  - `running`: the caller passes the set of card ids whose linked session or Pilot is running now.
  - `failed`: the card's most recent linked-work activity row is `failed`.
  - `needs_review`: the card sits in a column with role `review`.
  - `none`: the card has no `board_card_links` rows.
- **Due buckets** use local days:
  - `overdue`: before today, not done
  - `today`
  - `next7`: tomorrow through +7 days
  - `later`: after that
  - `none`: no due date

  Done means the card is in a column with role `done`.
- **Sort keys:** `manual` (column order, then position), `priority`, `due`, `start`, `title`, `created`, `updated`; direction `asc` or `desc`. Missing values sort last in both directions. Ties keep manual order.
- **Board layout with a non-manual sort:** cards inside each column follow the sort, and drag-to-reorder inside a column is off. Moving a card between columns still works and appends it. The header shows "Sorted by {key}".
- **Saved views** (v4 table `board_views(id, board_id, name, position, spec_json, layout_json, created_at, updated_at)`):
  - A built-in "All cards" tab (no filter, manual sort, board layout) always comes first and can't be deleted.
  - "Save view" saves the current spec and layout under a name.
  - The tab menu has Rename, Duplicate and Delete.
  - Unsaved changes on a saved view show "•" on the tab, with Save / Revert.
- **Layouts:**
  - `board`.
  - `list`: grouped by `status` | `priority` | `label` | `project` | `due`, with collapsible groups.
  - `table`: column picker over title, status, priority, due, start, labels, projects, estimate, created, updated and custom fields. Columns are resizable (minimum 60 px). Title, status, priority, due and labels can be edited inline. Column choice and widths are stored in the view's `layout_json`.
- **Bulk select:**
  - ⌘-click (Ctrl-click on Windows/Linux) toggles a card, and Shift-click selects a range in the current order. Works in board, list and table.
  - A floating bar shows "N selected" with Status…, Priority…, Labels…, Archive, Delete and Clear.
  - Archive and Delete use the C2 undo toast. A bulk delete is a held delete of every selected card.
  - Escape clears the selection.
- **Keyboard** (only when no text field has focus; otherwise the key types normally):

  | Key | Action |
  |---|---|
  | `N` | New card modal |
  | `/` | Focus search |
  | `E` | Open the focused card's detail |
  | `Delete` / `Backspace` | Held delete of the focused card, or the selection |
  | `Esc` | Closes the drawer, then menus, then the selection (existing layering plus selection) |

  Arrows and Space keep their existing behaviour.
- **Command palette:** "Create card" (opens the board and the New card modal), "Go to board", and "Switch board…" (lists boards).
- **Performance:** list and table render only visible rows. The board layout stays unvirtualised until C6.
- Verification before each commit: `bun run check`, and `bun run native:check` when crates/ changes.

## Review Focus

1. **A saved view referring to a deleted label, column, project or custom field.** The row drops the missing values and an emptied row is ignored. Never an error, never zero results by accident. Tests in C4-1.
2. **Date filters across midnight and DST** (`today`, `next7`, `24h`). They are computed from local days and an explicit `now`, not wall-clock calls inside the engine. Tests in C4-1.
3. **Shift-click range selection after the order changed** (new filter or sort). The range follows the current visible order. Tests in C4-4 and C4-7.
4. **Shortcut keys while typing** (search box, composer, inline table edit, comment box). `N`, `E`, `/` and `Delete` type normally. Tests in C4-5 and C4-8.
5. **Inline table edits racing a refresh** from the other app. Unsaved inline text is kept until commit or Escape. Tests in C4-4 and C4-7.

### Task C4-1: Store query engine, saved views and bulk operations

**Files:** create `crates/board-store/src/views.rs`; modify `crates/board-store/src/{schema.rs,migrate.rs,meta.rs,labels.rs,lib.rs}`; tests in `crates/board-store/tests/views.rs`

**Interfaces (produces):**
- `ViewSpec { query: String, rows: Vec<FilterRow>, sort: SortSpec }` with `FilterRow { field: String, op: Op /*Is|IsNot*/, values: Vec<String> }` and `SortSpec { key: SortKey, dir: Dir }`. All serde camelCase; a JSON round trip is stable.
- `query_cards(conn, board_id, spec: &ViewSpec, now_ms: i64, tz_offset_minutes: i32, running: &HashSet<String>) -> Result<Vec<String /*card ids, ordered*/>, String>`
- `CardIndexRow { card_id, column_id, number, title, priority, due_at, start_at, estimate_minutes, labels: Vec<String>, projects: Vec<String>, created_at, updated_at, fields: BTreeMap<String /*field_id*/, String /*value_json*/> }` and `card_index(conn, board_id) -> Result<Vec<CardIndexRow>, String>` (one batch read).
- Saved views:
  - `View { id, board_id, name, position, spec_json, layout_json, created_at, updated_at }`
  - `list_views(conn, board_id)`
  - `create_view(conn, board_id, name, spec_json, layout_json) -> View`
  - `update_view(conn, view_id, name: Option<&str>, spec_json: Option<&str>, layout_json: Option<&str>)`
  - `delete_view(conn, view_id)`
  - `move_view(conn, view_id, index)`
- Schema v4: the `board_views` table. The migration is restructured into per-version steps and stays idempotent.
- Bulk:
  - `set_priority_many(conn, card_ids, priority) -> String`
  - `set_label_many(conn, card_ids, label_id, on: bool) -> String`

  Each runs in one transaction, with one activity row per card that changed.
