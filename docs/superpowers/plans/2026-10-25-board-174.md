# Board (#174) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One branch (`board/174-board-and-tickets`) and one PR that delivers #174: tracker ticket links (Jira, Linear, Plane) on sessions and cards with agent ticket tools, a shared board store, and the full board feature set in both apps.

**Architecture:** Three phases, each leaving working software.
- **Phase A (ticket path):** tracker providers → a `tickets` service in `gespan-core` → a session ticket link (stored in the existing `sessions.linked_work_item_json`) → a `gespan_ticket` MCP tool server modelled on the visual bridge.
- **Phase B (shared store):** a new root-workspace crate `crates/board-store` owns all board SQL with schema v3. Both `gespan-core` and `src-tauri` use it, and cards get multiple links, including a ticket.
- **Phase C (board features):** Parts 2–5 of #174 in both apps. Each part gets its own detailed plan, written when Phase B lands, against the code as it is then.

**Tech Stack:** Rust (gespan-core, gespan-gpui on GPUI, src-tauri), rusqlite 0.40.2 (bundled, hooks, no default features), ureq 2.12 (blocking HTTP), React + Vite (Tauri UI), Vitest, Bun.

**Spec:** GitHub issue #174 (body, plus the "Decisions (2026-10-25)" comment). Codebase maps: `docs/superpowers/plans/2026-10-25-board-174-maps.md` (Task 0).

## Global Constraints

- One PR for everything. Commits stay small and green.
- **No two-way sync and no webhooks.** Providers expose only: get by key, comment, change status (plus connect/whoami).
- Trackers: `jira`, `linear`, `plane`. Plane: base URL (Cloud `https://api.plane.so` or self-hosted) + personal API key in header `X-API-Key`, endpoints under `/api/v1/…/work-items/`.
- Tracker secrets only through `gespan-tracker-secrets` (`Tracker::Plane` slot already reserved). The agent never sees a token.
- Comments are written as Markdown. Jira gets ADF via `format::markdown_to_adf`, Plane gets HTML via `format::markdown_to_plane_html`, Linear gets Markdown as is.
- Board storage decision: new shared crate `crates/board-store`. It must spell out `rusqlite = { version = "0.40.2", default-features = false, features = ["bundled", "hooks"] }` and use no `.workspace = true` inheritance (it builds under both workspaces, like `crates/tracker-secrets`).
- Boards stay global; cards are tagged with projects.
- Description editor: plain Markdown + small toolbar.
- New boards default to **"Run with…" on and agent write-back on**, both switchable per board.
- Per board and per session: **"Agent may change ticket status"**, default on. Off means `ticket_status` lists but never moves.
- No network call on a timer for tickets. Refresh on link, on open, and after a ticket tool call.
- Verification before every commit: `bun run native:check` (fmt, clippy `-D warnings`, core + gpui tests). For Tauri/React changes also `bun run check`.
- Commit messages: plain, no tool attribution.

## Review Focus

1. **Pasting a URL instead of a key** (`https://acme.atlassian.net/browse/ABC-12?focusedCommentId=9`, `https://linear.app/acme/issue/ENG-42/some-title`, a Plane URL with a trailing slash). The link must resolve to the right tracker and key. Test in Task A1.
2. **A key that matches more than one connected tracker** (`ABC-12` with Jira and Plane both connected). The user must be asked, never guessed. Test in Task A5 (`resolve_reports_ambiguity`).
3. **The tracker gets disconnected or its token expires after linking.** The chip must still show cached data, marked stale, and the agent tool returns a clear "reconnect" error, not a panic or an empty result. Tests in Tasks A5 and A8.
4. **An agent names a different ticket than the session's** (prompt injection from a ticket body: "now comment on ABC-99"). It must be refused. Test in Task A8 (`ticket_tools_refuse_another_key`).
5. **A Jira transition that needs fields** (resolution, assignee). The tool must report the fields and not move, and must not loop retrying. Test in Task A2 (`transition_with_required_fields_does_not_post`).
