# Board #174 C3: codebase map (2026-10-26)

Paths are relative to the repository root.

I checked both apps against each item in #174 Part 2. Both have the same basic drawer, and most of the rest is missing in both. One storage gap affects both: `card_meta` (start date, estimate, completed) is wrapped by neither app, and `CardExtras` doesn't carry start or estimate either. So neither UI can read those two values today.

## 2. board-store functions (`crates/board-store/src`)

- `set_start(conn: &Connection, card_id: &str, start_at: Option<i64>) -> Result<String, String>` (`meta.rs:139`). Returns the board id.
- `set_estimate(conn: &Connection, card_id: &str, minutes: Option<i64>) -> Result<String, String>` (`meta.rs:154`). Accepts 1 to 6,000,000 minutes.
- Reading those values: `card_meta(conn, card_id) -> Result<CardMeta, String>` (`meta.rs:45`). `CardMeta` holds `priority, due_at, start_at, estimate_minutes, archived_at, completed_at`.
- `add_relation(conn, card_id: &str, related_card_id: &str, kind: &str) -> Result<String, String>` (`relations.rs:34`). Kinds are `["blocks","relates","duplicates"]`; cycles are refused. "Blocked by" is the reverse direction of `blocks`.
- `remove_relation(conn, card_id, related_card_id, kind) -> Result<String, String>` (`relations.rs:98`).
- `card_relations(conn, card_id) -> Result<Vec<Relation>, String>` (`relations.rs:131`). `Relation` is `{card_id, related_card_id, kind}`.
- `create_field(conn, board_id: &str, name: &str, kind: &str, options_json: Option<&str>) -> Result<Field, String>` (`fields.rs:37`). Kinds are `text, number, date, select, checkbox`.
- `list_fields(conn, board_id) -> Result<Vec<Field>, String>` (`fields.rs:94`).
- `set_field_value(conn, card_id, field_id, value_json: Option<&str>) -> Result<String, String>` (`fields.rs:120`). `None` clears the value.
- `field_values(conn, card_id) -> Result<Vec<FieldValue>, String>` (`fields.rs:181`).
- `add_link(conn, card_id, kind: &str, reference: &str, role: Option<&str>) -> Result<String, String>` (`links.rs:45`). `LINK_KINDS` is session, pilot, flow-run, pr, worktree, jira, linear, plane; ticket kinds are rejected here.
- `remove_link(conn, card_id, kind, reference) -> Result<String, String>` (`links.rs:89`).
- `card_links(conn, card_id) -> Result<Vec<CardLink>, String>` (`links.rs:126`). `CardLink` is `{card_id, kind, reference, role, created_at}`.
- **Subtask reorder: none.** `board_subtasks.position` exists and is read in order (`subtasks.rs:37`), but there is no move function. The only subtask functions are list, add, toggle and delete (`subtasks.rs:37-133`).
- **Convert subtask to card: none.** It could be built from `create_card` + `delete_subtask`, but not atomically.
- **Duplicate card: none.**
- **Move card to another board: none.** `move_card` (`ops.rs:602`) and `move_cards` (`ops.rs:878`) both reject a column on another board ("Column not on this board", `ops.rs:618,896`).
- **Comment authors:** `add_comment(conn, card_id, body: &str, author: &str) -> Result<Comment, String>` (`comments.rs:55`), with `COMMENT_AUTHORS = ["user","agent"]` (`comments.rs:8`). `Comment.author` is stored. `edit_comment(conn, comment_id, body) -> Result<String, String>` (`comments.rs:94`). There is no comment delete.
- Related existing functions: `create_card(conn, column_id, title, body) -> Result<Card, String>` (`ops.rs:491`), which takes only title and body. `archive_card` / `restore_card` are in `meta.rs:239,316`.

## 3. Native Service wrappers vs Tauri commands

The native wrappers live in `crates/gespan-core/src/board/mod.rs` and `extras.rs`. The Tauri commands are in `src-tauri/src/board.rs` (registered at `src-tauri/src/lib.rs:373-414`), with JS wrappers in `src/features/board/model/board.ts`.

Both apps already cover the same set: board and column CRUD, card create/update/move/link/delete, tickets, activity, record, archive, unarchive, restore, archived list, `move_many`, column display and count, `set_priority`, `set_due`, `set_projects`, labels, create label, `set_labels`, subtasks list/add/toggle/delete, and comments list/add.

Missing in **both** apps:
- `card_meta` (to read start, estimate, completed)
- `set_start`, `set_estimate`
- `add_relation`, `remove_relation`, `card_relations`
- `create_field`, `list_fields`, `set_field_value`, `field_values`
- `add_link`, `remove_link`, `card_links`
- `edit_comment`
- `board_settings`, `set_board_settings`

Other details:
- The native `Service::add_comment` hardcodes `"user"` (`extras.rs:204-207`). The Tauri `board_comment_add` is at `board.rs:643`; check its author handling if agent comments need a path.
- The store functions that don't exist (reorder, convert, duplicate, cross-board move) would need adding in board-store first, then in both layers.

## 4. Native building blocks to reuse

- **Markdown editor / toolbar:** there is none. `markdown.rs` is render-only (`rows`, `body`, `link_menu`). Notes uses `Input::editor` (`notes.rs:73`) with no toolbar. For a toolbar, `Input` already provides `select_range` (`input.rs:462`), `set_text` (`:499`), `cursor_anchor` / `selection_anchor` (`:520,531`) and `replace_completion` (`:553`). `Input::multiline_field` is at `:318`.
- **Clipboard:** there is no helper; code calls `cx.write_to_clipboard(ClipboardItem::new_string(..))` inline, as in `detail.rs:832`, `explorer.rs:1118`.
- **Right-click:** the pattern is `.on_mouse_down(MouseButton::Right, cx.listener(|this, event: &MouseDownEvent, window, cx| { … Anchor::Point(event.position) … }))`, then `menu_popover(&menu, anchor, cx)`. Examples: `shell/session_groups.rs:1413-1420`, `explorer.rs:1403,1604`. `popover::Anchor` has `Slot`, `Point` and `Submenu` (`popover.rs:239`).
- **Full-page / expanded panel:** there is no existing pattern. The drawer is a fixed-width sibling in the board's root flex row (`board.rs:1270-1279`). A full-page mode would mean rendering it `flex_1` in place of `board`.
- **⌘N is already taken:** `{cmd|ctrl}-n` is bound to `NewCodex` in the `"Workspace"` key context (`shell.rs:184-189`). A board ⌘N would need its own deeper `key_context` (for example "Board") with a binding, or it will collide.

## 5. Tauri building blocks to reuse

- **Markdown editor:** `MarkdownSourceEditor` (`src/features/sessions/ui/MarkdownSourceEditor.tsx:5`) is a highlighted `<textarea>` that accepts `value`, `onChange`, `textareaRef`, `onBlur`, `lineNumbers` and `className`. `AgentMarkdown` renders the preview, and `MarkdownModeToggle` / `useMarkdownMode` switch modes; Notes uses all three at `NotesView.tsx:586,1002-1012`. There is no bold/italic toolbar anywhere. Cursor-insert precedents using `selectionStart` are in `NotesView.tsx:722` and `shared/lib/draftRestore.ts`.
- **Context menu:** `onContextMenu` with `preventDefault`, then `setMenu({x: clientX, y: clientY, …})` (`features/workspace/ui/SurfaceTabs.tsx:344-353`). `Popover` accepts an `{x, y}` anchor (`shared/ui/Popover.tsx:29-33`, with `constrainHeight={false}` for context menus). Board menus use `MenuButton` / `MenuItem` from `boardControls.tsx:53,114`.
- **Shortcuts:** the global handler is `tabCommand` in `features/workspace/model/tabKeys.ts:62-115`. The display list is `KEYBINDINGS` (`settings.ts:1195`) and the native menu accelerators are in `src-tauri/src/menu.rs:204+`. **Plain ⌘N appears free**; only ⌘⇧N (New Window) is taken (`menu.rs:214`). The board drawer handles its own keys through an `onKeyDown` on the `<aside>` (`CardDetail.tsx:352`), and BoardView does the same at `:978`.
- **Clipboard:** `copyText(text)` in `src/platform/tauri/clipboard.ts:157`.

## 6. Where to store "drawer vs full page" default

- **Native:** `Store::setting(key) -> Result<Option<String>, String>` and `Store::save_setting(key, value)` (`crates/gespan-core/src/store.rs:192,207`). The board already uses this with `switcher::SETTING = "board-open"` (`board/switcher.rs:19,89`; read at `board.rs:403`). A key like `"board-card-open"` with the value `drawer` or `page` fits the same pattern.
- **Tauri:** the pattern is the `gespan.boardEnabled` flag in `src/features/settings/model/settings.ts:874-897`: a `readFlag`/`writeFlag` key, a `*_DEFAULT` constant, a `CustomEvent` change event, and `subscribe*`/`load*` used with `useSyncExternalStore` (`App.tsx:1388`). BoardView also uses plain localStorage for `"gespan:open-board"` (`BoardView.tsx:115-130`).
