# Board #174 C1: Parity base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tauri's board catches up with Native's card features, and Native gets multiple boards and real keyboard drag, so both apps start Phase C level.

**Architecture:** Both apps already share storage through `crates/board-store` (schema v3).
- **Tauri:** gains commands for the store functions it doesn't expose yet, then UI on top of them: card face, search/filter, and a docked drawer.
- **Native:** gains a board switcher, with the last-opened board stored through the existing `Store::setting` mechanism, and keyboard drag that reuses the existing drop-target rendering.

**Tech Stack:** Rust (board-store, src-tauri commands, GPUI), React + dnd-kit, Vitest (happy-dom), Bun.

**Spec:** GitHub issue #174 (Part 2 and Part 5), plus `docs/superpowers/plans/2026-10-25-board-174.md` (Phase C table, row C1). Map: `docs/superpowers/plans/2026-10-25-board-174-c1-maps.md`.

## Global Constraints

- Same branch and single PR as the rest of #174. Commit messages plain, no tool attribution.
- Both apps read and write the same `gespan.db` through `gespan-board-store`. No new SQL outside board-store.
- Tauri commands: `#[tauri::command(async)]`, `State<SessionStore>`, `store.lock_conn()`. Mutations call `notify(&app, board_id)` (event `gespan:board-changed`). JS arguments are camelCase. Every new command is registered in `src-tauri/src/lib.rs` and added to the `handlers` map of any test that renders through it.
- Priority labels are exactly `["None","Low","Medium","High","Urgent"]` (u8 index). Label colours are 6 hex digits without `#`.
- Activity rendering in Tauri matches Native's `"Changed {detail} · {actor}"` for `edited` rows that carry a detail.
- Copy: short, plain, sentence case. Tauri uses existing `boardControls.tsx` primitives (`MenuButton`, `MenuItem`, `NameInput`, `noDrag`).
- Verification before each commit: `bun run check`. For crates/ or gpui changes also `bun run native:check`.

## Review Focus

1. **A filter or search that hides cards during a drag** (Tauri). Dropping must still land at the right position among *all* cards in the column, not the visible ones. Native already maps visible to full slots (`full_slot`). Test in Task C1-2 (`drop_while_filtered_lands_between_the_right_cards`).
2. **Deleting the board that is currently open** in Native. Another board must open, never an error or blank. If none are left, a new default board is created through `default_board()`. Test in Task C1-4.
3. **Keyboard drag cancelled with Escape, or a reload arriving mid-drag** (Native). The card stays where it was and nothing is written. Test in Task C1-5.
4. **Editing in the Tauri drawer while Native writes the same card** (board-changed event mid-edit). An unsaved title or notes draft must not be overwritten by the refresh. Test in Task C1-3.
5. **A label or project filter whose label gets deleted or renamed elsewhere.** The filter must drop the missing id without crashing or hiding everything. Test in Task C1-2.

**Interfaces:**
- Consumes: `drop_target` rendering, `full_slot`, `resolve_card_drop`, `Service::card_move`.
- Produces: keys on a focused card:
  - **Arrow up/down:** move focus to the previous or next visible card in the column. Arrow left/right moves focus to the same index in the neighbouring column (clamped).
  - **Space:** pick up the card, which enters `kb_drag` and shows the drop line at its current slot. While lifted:
    - arrows move the target slot and column (the drop line follows);
    - Space or Enter drops: `card_move` through the full-slot mapping, `"user"` actor;
    - Escape cancels, writing nothing.
  - **Enter, not lifted:** opens card actions as today. "Move to…" stays.
